# 质量事件流程 · S5 自检 + 交付闸门

> **流程位置**：S2b 报告之后、S6 终审之前。
> **本 skill 双重身份**：① **自检节点**（**复用** `oos-investigation-review`，同一把尺子）；② **交付闸门的宿主**（2026-09-25 由 `pharma-defect-response` Phase 8 与 `pharma-defect-response-notes` 汇总迁入；**后者已归档至 `.archive/`**）。
> **不新建成文环节**：成文已在 S2b 完成；本步只做**质量关**。

## 一、与 S6 的分工（先分清）

| | S5 自检（本步） | S6 终审 |
|---|---|---|
| 性质 | **机器自查**（同一把尺子：调 `oos-investigation-review` 的 8 维 D0–D7） | **审核人定夺**（人工或审核人视角） |
| 目标 | 改到自己过——不把明显问题退给审核人 | 判定定稿、对判断做最终取舍 |
| 出口 | 全绿 → 交 S6；不绿 → 回 S2b 修订 V(n+1) | 通过 → 交付；不通过 → 退回 |

**自检不过不得提交终审。** 自检不当终审：S5 的结论不能代替审核人决断。

## 二、自检（复用 `oos-investigation-review`）

1. 加载 `oos-investigation-review`，对 `03_investigation_report_V(n).md` 跑 **8 维审核（D0–D7）**，按其文档类型选权重向量
2. 重点核它的三条硬线：**程序优先原则**（禁止逻辑倒置：不得用"结果看起来合理"反证程序无问题）· **叙事顺序**（不得从"检查发现"倒叙）· **风险评估落点 D7**（落点须在质疑对象，不得写"影响可忽略/风险较低"）
3. **它的审核边界要记住**（见该 skill「审核边界声明」）：它审**叙事质量与逻辑合规性**，**不审**调查表单完整性、调查是否逐条确认、**证据附件是否齐全**——后半截正是本 step「交付闸门」要补的

自检结果处理：命中的问题项**就地修订**（只动组织与语言层，不改结论与定级）；若发现需要改结论/定级 → **回 S2b**，不在本步改。

### 方向已回应检查（若报告引用了体系维度扫描）（2026-09-25 定，方案 A）

- 报告引用了 `pharma-gmp-gap-scan` 的 `findings` 时，逐条核 **`state = suspect`** 的维度在报告中是否**有交代**
  （有交代 = 报告里说明该方向已排查并给出结论；无交代 = 记为待补项）
- **`possible` / `not_indicated` 的维度不作为检查项**（前者是常见关联面、后者是明确排除，均无义务写进报告）
- 本检查**只判“有证据的方向有没有被漏掉”**，**不判根因深度、不判调查是否充分**——后者是审核人决断
- 依据：`suspect` 的定义是“事件描述中有直接措辞指向该维度，必须引用原文片段”，属**有证据的方向**；`possible`/`not_indicated` 只是枚举视野，不得抬为义务

### 历史数据回溯检查（根因落在方法／标准／仪器／数据类时；2026-09-25 补）

- **触发**：根因为方法／标准类（影响结果准确性）、仪器／数据类，或报告引用了历史数据回溯结论
- **检查三件**：① 报告（或其风险影响评估节）**是否含历史数据回溯结论**（可靠／需复验／无法判定，三选一，不得空缺）；② **时间窗与批次范围**是否写明（方法类：起点 = 方法／标准生效时点，终点 = 纠正并确认）；③ 若结论为“需复验／无法判定”，**落地归属**是否写明（留样复测 / 年度质量回顾 → QMS 年度质量回顾与稳定性线）
- **判不合格的情形**：根因为方法／标准类而报告**通篇无历史数据回溯**；或写了“历史数据可靠”却**未说明事件发生时有无“当场抓住”的手段**（无手段 → 不得判“可靠”）
- 本检查只判**有没有做、有没有写清**，不重做定量评估（评估本身归 `pharma-data-integrity-assessment`）

## 三、结构完整性检查（逐节齐 + 每节有实质内容）

**只查"标题在不在"不够——空标题（标题下无实质内容）一律判不合格。**

### A. 调查方案（S2a 产物 `02_investigation_plan_V*.md`）

| # | 必备节 | 通过判据 |
|---|---|---|
| 1 | **目的** | 三段齐：① 事件描述（时间/人员/地点/检项/批次/结果/限度和违背的规定）② **引用 S1 结论** ③ "为排查该原因，特制定本调查方案" |
| 2 | **范围** | 一句话限定到引发本事件的那一环节（不得写成"全面调查"） |
| 3 | **3.1 原因识别** | 3.1.1 Ⅰb 已确认无异常的维度 + 发现异常的细节及因果链；3.1.2 公式/变量分解已列出 |
| 4 | **逐变量调查与排除** | 每个变量一节；每节含"查什么记录（编号+版本）→ 数据表（含接受标准）→ **可排除**结论" |
| 5 | **确认方法设计** | 三列表齐（确认方法 / 可能结果 / 对应的原因）；**必须含"需要进一步调查"分支**；结果判据可量化 |
| 6 | **操作方法** | 分组执行细节；**组间清洗/活化写清**（防串扰）；依据文件编号+版本 |

**常见不合格**：跳过逐变量排除直接给实验；初疑原因未指到具体条款；确认方法表无迭代分支。

### B. 调查报告（S2b 产物 `03_investigation_report_V*.md`）

> **判据口径：按要素判、不按节号判（2026-09-25 实测修正）**。根因/影响评估/CAPA/结论可**顶层单列**（§4/§5/§6/§7），也可**嵌在 §3 内容下**——只要**要素齐全即视为结构完整**，**不得因节号层级不同判缺**。实例：真实 123456 报告用 3.2.3 管理断点 / 3.2.4 根本原因判定 / 3.3 调查结论 / 3.4 影响评估 / 3.5 预防整改措施，要素与下表一一对应，但节号完全不同。

| # | 必备节 | 通过判据 |
|---|---|---|
| 1 | **目的** | 含调查起止日期、人员、方案编号（含阶段性报告编号）、“给出根本原因 / 最可能原因” |
| 2 | **范围** | “针对〔编号〕调查的总结、分析、评估与报告” |
| 3 | **3.1 首次方案执行与结果** | 日期+人员+按方案做了什么+结果+**与预期是否一致** |
| 4 | **3.2 进一步调查** | 按轮次分节（日期/依据上轮编号/做法/数据/差异）；数据不足时如实写“无法确定原因” |
| 5 | **3.3 数据汇总** | 表格齐（各组实测值/均值/与限度关系）；必要时附辅助数据（如电位斜率） |
| 6 | **3.4 分析与判定** | 对照方案预设情形逐条落位；已排除/保留/未定分别写明 |
| 7 | **3.5 现行文件体系中的管理断点** | 触及文件/机制层时**必写**（引条款原文与版本 → 断点在哪 → 支撑系统原因） |
| 8 | **4 根本原因** | **直接原因与根本原因分开写、主语不同**；每条挂依据（实验轮次/数据/记录编号）；按 J1 定终点 |
| 9 | **5 风险/影响评估** | 落点=质疑对象（J2）；核实范围=质疑路径边界（J3）；禁减责与消极辩护措辞；**含影响方向性**（假阳性／假阴性，不得断言“偏高不会掩盖低含量”）；**根因为方法/标准/仪器/数据类时须含历史数据回溯结论 + 落地归属**（见 §二「历史数据回溯检查」） |
| 10 | **6 CAPA** | **两分（纠正/预防）齐**；四要素含**交付物**；有有效性核查计划 |
| 11 | **7 结论与待核实项** | 一段话收口（查了什么→查到什么→根因→影响→如何处置）+ 待核实/待批准项 |

## 四、信息完整性与批次信息检查（字段级）

### 1. 必填字段（缺一即不合格）

| 组 | 字段 |
|---|---|
| 编号 | 事件编号（OOX/偏差/无效测试编号）、方案编号、报告编号 + **版本号** |
| 涉事对象 | 产品/物料名称、规格、**批号**、样品编号、异常数据类型 |
| 检项与标准 | 检验项目、检验结果、标准限度（**含药典来源**）、质量标准/方案**文件编号 + 版本** |
| 时间与人员 | 发生/发现/调查起止日期、检验人、调查人员、审核人 |
| 记录依据 | 实验记录本编号及页码、图谱编号、数据表编号 |
| 依据文件 | 检验操作规程 / 仪器操作规程 / SOP 的**编号 + 版本** |

### 2. 样品与批次信息（用户强制项）

**凡涉及样品，批次信息必须明确到可追溯：**

| 项 | 要求 |
|---|---|
| **批号** | 必填。**写成“该批”/“某批”而无编号 → 判不合格，退回补** |
| 无批号情形 | 用**样品编号**代替并说明原因（如委托方样品、留样） |
| 样品来源/类型 | 市售/中试/留样/复检样/委托方样品；取样人+日期+取样方案编号 |
| 样品处置 | 已制备供试品 / 原样 / 备样 / 重取样（重取样需取样方案编号） |
| 涉及批次范围 | 多批时给 included / excluded + 排除理由；不得写“所有批次” |

### 3. 结构与信息检查的记录方式

逐项打勾（✅/❌ + 缺失项），**不合格项先回 S2a/S2b 补，不得带缺过闸**（**例外：仅因脱敏占位符而不合格 → 不退回、不阻塞，见下方 4.**）。

### 4. 脱敏占位符（照判但不阻塞；2026-09-25 用户裁决）

> **口径锚点**：编排器「九·五 脱敏占位符处置口径」（本步只做落地，不另立一套）。

字段为**占位符**（空着 / `xxx` / 随意填写 / `待定`）时：

- **照判缺项**，**不得**当作“已具备”——把 `xxx` 当责任人、把空值当已填写，会让“合格”判定造假，比不写更危险
- **但不作为阻塞项**：不退回 S2a/S2b，改为 ① 逐条登记 `_meta/pending_items.md`；② 正文与交付物**显式标注**该字段为占位符待回填
- **显式标注是硬要求**：正文里每个占位符处须带说明（如 `责任人：xxx（占位符，待回填）`），**不得裸留 `xxx` 而无说明**——静默空缺会让审核人（S6/人）把占位符当真值审。交付物首部须有一段「数据形态声明」（本次数据经脱敏 + 待回填清单）
- **结构性缺失仍不放松**：整节无内容（空标题）、无交付物、无核查计划 → **照旧判不合格并退回**（占位符只免“阻塞”，不免“缺内容”）

## 五、交付闸门（三层物理分离 + grep 自检）

### 1. 目录结构

```
report_<编号>_V{n}.0/
├── 01_narrative.md            ← 唯一交付物（叙事正文 + 附件清单 + 签署栏）
├── 02_attachments/            ← 附件实体
└── _meta/
    ├── skill_invocations.yaml   ← 组合流程调用链
    ├── fact_index.yaml          ← 事实与引用索引
    ├── revision_history.md      ← 修订历史（保留近 3 版）
    ├── pending_items.md         ← 待人工补齐项
    ├── judgment_trace.yaml      ← 判据调用记录 + pending_reviewer_decision
    └── query_log.md             ← 流程中问询记录
```

正文只保留：**叙事正文 + 附件清单 + 签署栏（编制/审核/批准留白，手工签）**。

### 2. grep 自检（出现即判不合格）

| 检查项 | 期望 |
|---|---|
| `待补充\|待确认\|流程调用\|skill_invocations\|事实与引用索引\|修订历史` | 正文 **0 处** |
| 内部编号 `F\d\|V\d\|CM\|PA` | 正文 **0 处** |
| `默认合规\|推定合格` | 正文 **0 处**（J3 用词纪律：应写"不在质疑路径上，故未排查"） |
| 评估层元术语（"维度""锚点""评分"） | 正文 **0 处**（GMP 领域术语保留） |

**防自爆排除项（2026-09-25 实测发现）**：

- **报告编号与版本标识行不计入命中**：如 `报告编号: 123456-RPT-V2.0`、`编制日期` 行——`V\d` 只判**正文陈述里的内部编号**，不判文件编号与版本号
- 命中后**先判性质**：是真内部编号（应删）还是文件编号/版本（应保留）——后者**不改**
- **适用范围**：本闸门只对**新产出**强制三层分离；**历史产物（新规范生效前）按其当时体例，不追改**（例：2026-07 的 123456 报告将修订历史置于正文末）。**2026-09-27 泛化（用户确认口径）**：本批次新增/修改的**全部闸门条款**（版本一致性、签字栏、留痕齐备、双出口裁定、时限检查）同此口径——只对**新事件、新产物**强制；既有事件目录按其当时体例保留，**不追溯整改、不追溯重判**；唯二例外：① 数据完整性缺陷（结论无据、来源不实）；② 用户明确要求整改。
- **否定式表述不计入命中（2026-09-25 实测发现，第二类误报）**：`不得 / 不能 / 禁止 + 默认合规 / 推定合格`（如“不能据此默认合规”）属**正确用法**——它是纪律的**正面声明**，不是消极辩护。只有**陈述式断言**（“…默认合规”“…推定合格”）才判命中。**判命中前先读上下文，不得只凭关键词。**

### 3. grep 自爆规避（否定用法的安全措辞）

检查词若出现在**正确方向的否定句**里，会被 grep 误命中。先判"概念错误用法"还是"否定正确用法"，后者**改安全措辞、不改原意**：

| 危险措辞 | 安全措辞 |
|---|---|
| 不为…逐条复述 | 通用要求由上位规程统一承载，下位文件只补本环节特有控制点 |
| 下位不复述上位 | 下位文件只写本环节特有控制点 |
| 不被下位架空 | 下位未细化时直接在本环节补齐控制点 |

### 4. `_meta/` 的写入门禁

- **`.yaml` 扩展名有语法校验**：`fact_index.yaml`、`skill_invocations.yaml`、`judgment_trace.yaml` 必须写**真 YAML**（列表 / key-value）；**Markdown 表格会被拒**，不要直接搬表
- `revision_history.md`、`pending_items.md`、`query_log.md` 是 `.md`，可用表格
- `judgment_trace.yaml` 必含 `pending_reviewer_decision`（J1 终点 / J2 落点 / J3 范围充分性）

### 5. 体裁与版本重组

- **默认体裁**：三段式调查报告（目的/范围/内容）。紧凑表体裁仅两种情形选用：用户明确要求，或单条极小事件；选了紧凑表体裁**仍须过全闸门**
- **版本重组（V(n)→V(n+1)）只动文件组织与语言层**：调查结论、定级、judgment_trace 判断（J1 终点 / J2 落点 / J3 路径边界）沿用既有定稿
### 6. 版本一致性、签字栏与留痕齐备检查（2026-09-27 补，不过不得进 S6）

**(a) 版本一致性三对齐**：① 文件名版本 = 文内版本；② 交付物版本 = 下游文件（`03b`/`03d`/`06`/`07`）引用版本 = `_meta/skill_invocations.yaml` 记录版本；③ 修订历史表覆盖当前版本与前版差异。任一不齐 → 不绿，回 S2b 对齐（**只动版本标识层，不改结论**）。

**(b) 签字栏纪律**：AI 只填「待签 + 建议」；签字人**姓名 / 日期留白**，或注明来源（如「源 = 用户会话批准，2026-09-26 23:41」）。同一份文件内**不得出现自相矛盾的签署状态**（实测：`07` §三 已填「认可 + 质量负责人 + 日期」而 §五 签署栏又「留白待签」）。

**(c) 审核留痕齐备**：S2a 审核 `02b_plan_review.md`、S2b 审核 `03b_report_review.md`、GMP AI 终审 `03d_gmp_review.md`、S3/S4 若跳过 → `03c_skip_S3_S4.md`。**缺任一 → 不绿**。

**(d) 双出口裁定留痕**：走「报告已含」路径时，`03c_skip_S3_S4.md` 或 `_meta/skill_invocations.yaml` 的 `process_deviation_log` 须含**裁定人 / 时间 / 理由**。

### 7. 时限检查

发现日 → 调查所属日跨度超 S1 skill §八 建议值时，`01_initial_assessment.md` 与 `01b_info_request.md` **两处**均已登记延期申请 / 偏差编号（或已按占位符登记 pending_items）；未登记 → 不绿。

### 8. 叙述关（脱表阅读 · 硬闸门；2026-09-27 定）

**动作**：**只读叙述、跳过所有表**，逐节验三项——① 结论能否从叙述里读出来 ② 依据是否在文中（记录/图谱/数据编号入句）③ 是否存在“读不懂为什么”的段。

| 结果 | 处置 |
|---|---|
| 三项均过 | 过闸 |
| 任一项不过 | **不绿** → 回 S2a/S2b（缺陷线回其相应 Phase）重写叙述，不得交付 |
| 不适用 | 必须**写明理由**（如“本件无推理段”）→ 可过，**不得静默跳过** |

**规则依据**：`pharma-report-narrative`（R0–R6 泛化 + 表格准入三规则 + 本关细则）；交付物应附该事件“脱表阅读结论”（过/不过/不适用+理由）。

## 六、出口

**路径差异（重要）**：**「已查明根本原因」路径跳过 S2，无 `03_investigation_report`**——此时交付物为 `01_initial_assessment.md`（S1 结论）+ `04_risk_assessment.yaml`（S3）+ `05_capa.yaml`（S4），**五道关对这批文件执行**：结构完整性按「结论段 + 两份 YAML 的要素集」判，信息/批次、**叙述（脱表阅读）**、grep、`_meta/` 四道关不变。

```
全绿（自检 8 维无未处理项
      + 方向已回应（若引用体系维度扫描：suspect 方向均有交代）
      + 结构逐节齐且每节有实质内容
      + 必填字段齐、批次信息明确
      + 叙述关通过（脱表阅读：结论能从叙述读出、依据在文中）
      + grep 全绿
      + _meta/ 六件套齐）
  → 交 S6 终审
不绿 → 回 S2a/S2b 修订 V(n+1)，不得往下走（**例外：仅因脱敏占位符不绿 → 不阻塞，照常交 S6，见下方「占位符例外」**）
```

**五道关的顺序**：结构 → 信息/批次 → **叙述（脱表阅读）** → 语言 grep → `_meta/` 完整性。任一道不过，后续不必跑。

> **占位符例外（2026-09-25 用户裁决）**：出口条件里的“必填字段齐 / 批次信息明确”若**仅因脱敏占位符**而不满足 → **不判阻塞**：流程照常交 S6，但必须 ① 已登记 `pending_items.md`；② 交付物已声明数据形态与待回填清单；③ 正文占位符处已带标注。**结构性缺失（整节空、无交付物、无核查计划）仍不绿。**

## 七、不做

不改结论、不定级、不写 CAPA、不代替审核人决断、不做成文（已成文）、不发布。

## 八、已知陷阱

0. **规则未试跑就交付（2026-09-25 实测教训）**：本闸门的检查规则**必须先拿真实历史产物跑一遍**再依赖。未试跑的规则会两种翻车——① **自爆**：`V\d` 命中报告编号 `123456-RPT-V2.0` 与修订表版本号，产生假阳性；② **误判**：按节号判结构，会把要素齐全但层级不同（嵌在 §3 下）的合格报告判为缺节。**新增或修改任一条检查规则后，用 `<质量事件根目录>/` 下的真实报告回归一次。**
1. **自检当终审**：把自己的 8 维结论当审核人意见，直接交付
2. **过闸只看 grep 绿**，不看 `_meta/` 六件套是否齐
3. **把 `_meta/` 内容写进正文**（修订历史/待补项/调用链混入 `01_narrative.md`）
4. **grep 命中否定用法就改原意**（应用安全措辞）
