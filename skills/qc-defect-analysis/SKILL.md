# QC自检缺陷分析 (QC Self-Inspection Defect Analysis)

## 概述

分析QC实验室自检（内部审计）缺陷数据的工作流。处理原始Excel数据→按责任班组/月份/缺陷类型多维度分类→根因归类→提出CAPA措施→年度同比趋势判断→高风险低频事件识别。

**默认聚焦：原辅料+包材及水分析组**。分析时自动按责任班组筛选，也可切换至其他班组。

适用于：QC实验室月度自检、GMP自查、质量趋势分析。

## 十问分析框架（事件级与周期回顾通用）

以下 10 个问题构成分析的完整框架，**事件级统计与周期/年度回顾共用这一套问题**（2026-09-25 确认：原 `qc-periodic-review` 的十问与此完全相同）。分析时逐一评估覆盖情况：

| # | 问题 | 目的 | 数据来源 | 覆盖状态 |
|---|------|------|---------|---------|
| 1 | 哪类问题发生最多？ | 找高频风险方向 | 缺陷分类统计 | ✅ 内置 |
| 2 | 哪些产品/批次/车间/设备/班组集中？ | 找风险聚集点 | 房间级热力 + 班组×类别矩阵 | ✅ 扩展 |
| 3 | 哪些检测项目 OOS/OOT/异常最多？ | 找实验室或工艺薄弱点 | ❌ 非本数据源范围 | ⏭️ 跳过 |
| 4 | 哪些工艺步骤偏差最多？ | 找过程控制薄弱点 | ❌ 非本数据源范围 | ⏭️ 跳过 |
| 5 | 根因最多集中在哪里？ | 找系统性原因 | 根因五类法归类 | ✅ 内置 |
| 6 | 哪些问题重复发生？ | 判断 CAPA 有效性 | 跨年分类对比、重复率 | ✅ 内置 |
| 7 | 哪些问题严重性高但频次低？ | 找高风险低频事件 | 严重性分级 + 频次交叉 | ➕ 新增 |
| 8 | 哪些偏差关闭周期长？ | 找调查效率瓶颈 | ❌ 25/26年无关闭日期字段 | ➕ 标注局限 |
| 9 | 哪些 CAPA 逾期或效果不佳？ | 找质量系统问题 | ❌ 25/26年无措施日期字段 | ➕ 标注局限 |
| 10 | 是否存在逐月、逐季上升趋势？ | 识别持续恶化信号 | 月度趋势 + 同比 | ✅ 内置 |

**跳过说明**：Q3/Q4 属于 OOS/OOT 和工艺偏差分析范畴，需使用无效测试台账数据源（见 references/invalid-test-analysis-patterns.md）。Q8/Q9 需整改计划/关闭日期字段，当前25/26年数据源缺失，需在报告中明确标注。

**跨期对比（25vs26、同比）附加要求**：
- **归一化指标**：偏差率 = 事件数 / 生产批次；OOS 率 = OOS 数 / 检验批次；实验室异常率 = 异常数 / 检验总次数。不做归一化，产量变化会让绝对数误导结论
- **峰值月份必须结合**生产批量、产品切换、人员变动、检验负荷解读
- 分母的取数方式见「阶段 4 → 工作量数据接口」（先向用户索取 → 或取已有工作量报告 → 都拿不到则降级为绝对数并标注）

## 扩展分析模式：OOX/OOE/OOT/偏差/验证偏差

当数据源为OOX（OOS/OOT/OOE）或偏差/验证偏差文件时，需切换分析模式。此类数据通常来自 `质量事件/` 目录下的独立xlsx文件。

**关键特征**：
- 多sheet结构，每个sheet代表不同年份或部分（如`25年-1`/`25年-2`/`25年-3`/`25年-4`/`26年`）
- **各sheet列结构完全不同**，必须逐sheet确认列映射
- **ID可能缺失**：某些sheet（如OOE）的编号列可能全为`0.0`或空，需从描述文本中提取OOE/OOS编号
- **合并单元格溢出**：某些sheet的描述列可能被截断，溢出到相邻列（如`25年-3`中描述跨越col4-col5）
- **乱码行**：部分sheet包含合并单元格导致的乱码行（如`25年-3`的最后一行，报告人/日期/编号/部门/检项全部挤在col0），需用正则解析
- **重复数据**：不同sheet可能包含同一事件（如`25年-1`和`25年-2`都含00S2507010），需去重
- **类型混合**：同一文件可能同时含OOS、OOT、OOE三种类型，需分别统计

**OOE特有陷阱**：
- OOE（Observation of Exception，异常观察）的编号列常为空或`0.0`
- 编号需从描述文本中正则提取：`re.search(r'(OOE\d+)', desc)`
- 若无编号，可用日期+序号构造临时ID：`OOE{年份}{月份}{序号}`
- OOE的"是否实验室原因"列可能存在（如25年-4的col10），需纳入分析

**根因分类映射**（适用于所有质量事件类型）：
| 根因大类 | 典型关键词 | 示例 |
|---------|-----------|------|
| 人员(Man) | 人员/意识/未认真核对/误吸/混淆/未核对 | 分析员未核对样品信息 |
| 清洁方法/流程 | 清洁/CIP/清洗/消毒/冲洗/残留/网带/POM/乙醇喷洒/敞口/未更换 | 清洁方法无法覆盖特定部位 |
| 文件/方法(Method) | 文件/SOP/规程/描述不准确/规定不完善/细节/未固定 | 检验操作文件规定不完善 |
| 环境(Environment) | 乙醇/酒精/污染/交叉/环境/存放/碱残留/地漏/有机物浓度 | 样品存放靠近乙醇喷壶 |
| 器具/材料(Material) | 滴定杯/器具/容器/划痕/管路/气泡/手阀/超声波/容量瓶/晶片 | 容量瓶内壁划痕 |
| 设备(Machine) | 设备/仪器/烘箱/泵 | 烘箱温度漂移 |
| 其他 | 无法归入以上类别 | 原因未填写/待确认 |

**严重性推断**（与Phase 3.7互补）：
- 高（≥3分）：涉及数据完整性、法规符合性、直接影响检验结果
- 中（≥1分）：标识管理、记录规范性、流程执行
- 低：现场清洁、一般管理
- 关键词列表详见 references/oos-deviation-severity-inference.md

**CAPA有效性评估规则**（从invalid-test-analysis-patterns扩展）：
- 培训/SOP修订类措施：重复率最高，视为"无效"当同类检项在6-12个月内再次发生
- 工程控制措施（硬件升级/物理隔离/防呆设计）：视为"有效"
- 需区分"标记为重复"（用户标注）和"跨年度重复"（自动检测）
- 对重复事件需评估：(1) CAPA是否已实施 (2) 同类检项是否再次发生 (3) 根因是否相同

## 扩展分析维度

### Phase 3.5: 房间级热力分析

**跨年对比前必须先做房间名归一化**（见已知陷阱 #25）：打印各年房间列全部唯一值，人工确认映射后构建统一房间字典，再做统计。

利用26年独立房间列（col3），构建房间×缺陷类型交叉矩阵：

```python
room_cats = defaultdict(lambda: Counter())
for r in records:
    room_cats[r['room']][r['category']] += 1

# 识别房间级高发模式
for room, cats in room_cats.items():
    total = sum(cats.values())
    if total >= 3:  # 样本量阈值
        top_cats = cats.most_common(3)
        # 单一类型占比>60% 的房间标记为"特征性房间"
        if top_cats[0][1] / total > 0.6:
            print(f"🔴 {room}: {top_cats[0][0]}({top_cats[0][1]}/{total})")
```

**房间级分析价值**：
- 识别"特征性房间"（某类缺陷占比>60%）—— 指向系统性管理漏洞
- 发现跨班组共用房间的问题共性
- 为5S整顿和设施修缮提供精确靶向

### Phase 3.6: 班组×类别矩阵

构建各班组的高发缺陷类型差异矩阵：

```python
team_cats = defaultdict(Counter)
for r in records:
    team_cats[r['team']][r['category']] += 1

# 各班组 TOP3 缺陷类型
for team, cats in team_cats.items():
    top3 = cats.most_common(3)
    total = sum(cats.values())
    print(f"{team}({total}): {', '.join(f'{c}({n})' for c,n in top3)}")
```

**班组矩阵价值**：
- 识别各班组"独特问题模式"（某类缺陷占比显著高于全组平均）
- 为差异化培训和针对性CAPA提供依据
- 发现跨班组共性问题（如所有班组都有记录漏写）

### Phase 3.7: 高风险低频事件识别

对频次≤3条但可能影响数据完整性或产品质量的事件进行单独标注：

```python
# 从缺陷描述中推断严重性
HIGH_RISK_KEYWORDS = [
    '过期', '未处理', '未区分', '数据', '电子', '审核', '追溯',
    'SMP', 'SOP', '文件', '标识', '受控', '偏差', 'OOS'
]

def infer_severity(desc):
    desc_lower = str(desc).lower()
    score = sum(1 for kw in HIGH_RISK_KEYWORDS if kw.lower() in desc_lower)
    if score >= 2:
        return '🔴 高'
    elif score >= 1:
        return '🟡 中'
    return '🟢 低'
```

**严重性分级规则**：
- 🔴 高：涉及数据完整性（电子数据、审核追溯）、法规符合性（SMP/SOP/受控文件）、直接影响检验结果（过期试剂使用）
- 🟡 中：标识管理、记录规范性、流程执行
- 🟢 低：现场清洁、定置定位、一般管理

## 数据层：多源台账解析（原 pharma-qc-data-analysis，2026-09-25 并入）

处理跨年多 sheet 工作簿时的固定动作：

1. **读取与探形**：`openpyxl.load_workbook(data_only=True)`；列出全部 sheet 名；**按原样打印前几行（含表头行）**确认列布局，再写解析代码
2. **列索引漂移显式处理**：不同年份 sheet 的列数与列位不同（某年可能多一个"A"前缀列，某年字段顺序不同）。用表头文本对照 2–3 行实际数据确认映射后再编码。高频陷阱：`基础原因分类` 列会年际换位
3. **班组识别与确认**：打印「班组/组」列全部唯一值，**由用户确认纳入范围**——班组命名年际会变（如"理化组"→"产品理化"）
4. **按年分别解析**：各年用各自列索引，不共用映射表
5. **编号归一**：OOX/CAPA 对齐 CSV 中事件编号首字母 O 常被误打成数字 0，且同一文件内混用（`00S2501001` 与 `OOS2510016` 并存）。禁止对 `OOS`/`OOE` 前缀做精确匹配；用 `id.replace('0','O',2)` 归一，或改用数字后缀匹配
6. **源表优先级**：Excel 原 Sheet 是唯一事实源；`对齐数据_*.csv` 是派生对齐件，可能带转录错误（如关闭日期）。冲突时以 Excel 为准，并在报告数据说明节记录差异，**不得静默二选一**
7. **"按表格执行"的含义**：指源表（Excel 原 Sheet / CSV 原始标注），不是审核人的文字转述——转述可能写错（例：源表"文件"被写成"人员"）。应用分类前先回读源单元格，冲突时以源表为准
8. **与并行 agent 共同编辑报告**：打补丁前先 `read_file` 重读磁盘当前内容——kanban 流程中同级 worker 可能已改过同一文件，拿旧副本直接写会静默覆盖对方修订

其余陷阱（CAPA 字段写 "N/A" 视为无措施、空 root/detail_cat 行先剔除并报告条数、日期列里的编号按字符串读、长描述截断打印但全文保留供关键词匹配）见 `references/column-index-drift-patterns.md`、`references/capa-quality-assessment.md`、`references/oos-event-id-and-source-reconciliation.md`。

### 阶段 0：口径设计（分析动手前必须完成）

- **统计期**：明确日期范围（回顾类写清"截至当前已关闭"）
- **纳入范围**：发生日期在期内 + 状态为已关闭/已批准；作废记录不纳入；重复创建后合并的记录只算一次；同一事件导致多个 OOS 的计件规则按公司 SOP 定
- **各事件类型分别如何计入**：偏差 / OOS / OOT / 无效测试 / 复测 / 重检 / 验证偏差，提前定义，写进报告的数据说明
- **数据源优先级**：① eQMS/LIMS/MES 已批准记录 ② 部门年度 Excel 台账 ③ 邮件/聊天/笔记。正式回顾尽量用 ①；Excel 台账是补充，不是唯一来源
- **留痕**：源文件保留原件；记录导出系统 / 导出人 / 导出时间 / 查询条件 / 文件哈希 / 记录总数

### Phase 3: 分类统计

**Step 3.1 — 月度分布**
- 用 Counter 按月份统计，识别峰值月（2月/3月常为高发期）

**Step 3.2 — 缺陷类型分布**

缺陷分类体系（经验积累）：

| 大类 | 子类别（示例） |
|------|---------------|
| **记录规范 (40-50%)** | 内容漏写、内容写错、改错不规范、字迹不清晰、未按时审核/复核、未盖受控章 |
| **标识管理 (20-25%)** | 信息错误、信息不全/不清晰、缺标识、损毁/脱落 |
| **现场管理 (15-20%)** | 管理问题（制度/流程）、定置定位、不整洁 |
| **设备/设施 (5-10%)** | 未维保/未清消、不整洁、损坏 |
| **试剂/试液 (<5%)** | 过期、放置错误、配置错误 |

### Phase 4: 根因归类（五类法）

将缺陷按根本原因归入5大类：

| 根因大类 | 典型表现 | 占比参考 |
|---------|---------|:--------:|
| ① 记录填写规范缺失 | 漏写、字迹不清、改错不规范、内容写错 | ~30% |
| ② 标识管理执行不到位 | 标签过期/缺失/不一致、SOP升版后标识未更新 | ~25% |
| ③ 现场5S/设施维护 | 墙体损坏、污渍、异味、物品混乱 | ~25% |
| ④ 月度审核制度执行不力 | 未按时每月审核、审核人缺失 | ~13% |
| ⑤ 设备/设施维保缺失 | 回风口积灰、维保过期、无维保计划 | ~7% |

> ⚠️ 记录(①+④)通常占40%+，是质量管理体系最薄弱环节

### Phase 5: CAPA措施建议

按优先级分层：

**P1 — 记录填写规范**
- 制作《记录填写标准规范速查卡》张贴各操作间
- 新员工/轮岗人员上岗前实操考核（模拟填写+交叉复核）
- 班组长每月随机抽取3份已复核记录做"回头看"

**P2 — 月度审核执行**
- 设定固定"审核日"（如每月20日），班组交叉审核
- 未按时审核在班组例会通报，计入偏差事件
- 建议系统层面（LIMS）设提前3天预警

**P3 — 标识管理**
- 建立标识台账（受控编号/有效期/责任人），每季度统一检查
- SOP升版后，文件生效3个工作日内完成关联标识更新
- 统一标识模板和张贴位置

**P4 — 专项整改**
- 对高发区域（如取样间）安排全面5S整顿
- 设施修缮（墙体/回风口/异味源）联系工程部
- 整顿后设定每周定点检查

### Phase 6: 年度同比分析

**Step 6.1 — 对齐同期**
- 今年1-5月 vs 去年1-5月（同月数比）
- 若去年数据覆盖全年，需要过滤到同期月份

**Step 6.2 — 对比指标**

| 指标 | 含义 | 
|------|------|
| 缺陷总数 | 是否整体缓解 |
| 月度峰值 | 高发月是否转移/降低 |
| 分项变化 | 各缺陷类型的增减趋势 |
| 新出现/消失类型 | 新增问题类别或已消除类别 |

**Step 6.3 — 结论判定**

| 结论 | 判定标准 |
|------|---------|
| 显著改善 | 总量↓≥20%，且无新增高风险类型 |
| 局部改善 | 部分类型↓但总量持平或↑ |
| 无改善/恶化 | 总量持平或上升，高发类型无变化 |
| 结构变化 | 总量未变但缺陷类型分布变化 |

> 记录类缺陷（漏写、未审）是"容易提但难根治"的老大难——去年在说同样的问题，今年还在发生，说明整改措施未形成长效机制。

## 阶段 4：解读（五层结构）

**数据事实 → 趋势观察 → 可能原因（必须标注"可能"）→ 建议措施（按风险优先级）→ 需人工确认事项。**

重点维度：总量趋势（含归一化）、Pareto（根因/部门/产品/工艺步骤/检项/仪器六维）、OOS 专项十维度、重复事件三类（完全重复 / 相似重复 / 系统性重复）、CAPA 有效性（规则见 `references/capa-effectiveness.md`）。

### 三条"不重写历史"红线（最容易翻车处）

1. 把**未确认根因说成确认根因** → 只用 `final_root_cause` 字段；报告写"可能原因"时输出也必须写"可能原因"
2. 把**自由文本归类当成事实** → AI 分类只是 `ai_suggested_category`，人工复核后才进 `std_root_cause_category`
3. 因**数据缺失得出错误结论** → 数据质量章节是报告的强制部分，缺失就明说缺失

### 工作量数据接口（2026-09-25 定）

归一化与峰值解读所需分母：**生产批次数、检验批次数、检验总次数、当期在岗人数、加班/调休工时**。取数顺序写死为三级：

1. **先向用户索取** —— 按上述固定清单提问，拿到什么用什么，不臆测；
2. 或**从已有报告/台账取数** —— 工作量趋势报告（HTML）及工作量台账；
3. 都拿不到 → **降级为绝对数**，并在报告中显式写："归一化所需分母缺失，趋势判断以绝对数为基础，不可与产量变化解耦"。

「质量事件增加是否与工作量正相关」是**提问式分析步骤**：先取分母，再判相关；无分母时不得自行断言正相关。

### 数据质量章节（报告强制部分）

缺失字段比例、未关闭记录数、未分类根因数、无 CAPA 关联记录数、不能纳入趋势判断的数据限制。

## C式报告质量自检（输出前执行）

在完成所有分析阶段后、生成最终报告前，执行以下4项自检。这是C审核OOS报告时展现的"加一面镜子"模式——让已有的分析结果自己检查自己的逻辑连贯性。

### Q1: 因果链完整性检查
- 月度趋势→缺陷分类→根因归类之间是否有显式逻辑连接？
- 例："记录漏写占比从25年X%上升到26年Y%，这与根因①记录规范缺失的占比增加是一致的，说明..."
- 如果某两个相邻章节之间没有过渡句，标记为"需补充连接"

### Q2: 根因深度检查
- 前三大根因是否解释了≥70%的缺陷？如果不是，说明根因分类过粗
- 是否有至少一条根因达到了"系统管理层"（而非仅停留在"人员习惯不好"）？
- 如果有重复发生模式，是否指出了CAPA为何无效的系统原因？

### Q3: 趋势判断量化
- 说"改善/恶化"时必须附具体百分比和统计周期
- 禁用模糊表述如"略有上升""明显改善"，改为"从X%升至Y%（+Z个百分点）"
- 同比结论判定标准（显著改善/局部改善/无改善/结构变化）必须引用具体数据支撑

### Q4: CAPA分层检查
- P1-P4措施是否同时覆盖短期（<1月）、中期（1-3月）、长期（>3月）？
- 是否有工程控制/系统层面的措施？还是全部停留在培训/SOP修订？
- 每条措施是否有明确的责任人和可验证的完成标准？

**自检结果记录：** 在报告末尾追加"C式自检结果"段落，列出每项检查的通过/不通过状态和不通过项的具体整改建议。

### Q5: 重复发生闭环检查
- 对重复率最高的前 3 类缺陷，是否有专项 CAPA？
- 重复判定必须按"检验方法（平台+项目）"分组后匹配原因——同一原因分类出现在不同检验方法下不算重复（详见 `references/invalid-test-analysis-patterns.md`）
- 有重复但无针对性措施 = 不通过

**S4/Q4 标记为🔴时，必须在改进建议中补充至少一项中长期（>3月）或工程控制类措施。**

| D8 | 跨章节口径一致 | 每个数值型指标（均值/占比/周期）在趋势表与明细表两处逐列核对**取整方向**；措施/事件的优先级在正文措辞与 CAPA 优先序表两处交叉核对 | V1.0 曾被黄项命中两处：均值 19 vs 19.25 取整方向相反、"与 P1 合并"与表格归 P0 不一致 —— 结论对但口径不一致，GMP 直接出黄项 |

### 分析质量自检（Q1–Q6，沿用 C 式）

> Q1–Q5 的完整展开见上方「C式报告质量自检」；本表是**出报告前的逐项核对清单**（两者是详述与清单的关系，不要各写一套）。

| # | 检查项 | 生成时要求 |
|---|---|---|
| Q1 | 因果链完整性 | 相邻章节必须有过渡句；数据→结论不得跳跃（"3 条文件/方法问题"→"SOP 设计问题"必须显式搭桥） |
| Q2 | 根因深度 | 前三大根因解释 ≥70%；每项"系统性风险"必须给出下一步调查的具体方向（查哪份 SOP、哪批培训记录），禁止"需重点关注"式模糊表述 |
| Q3 | 趋势量化 | 改善/恶化判断必须附百分比 + 统计周期；禁止"略有上升""明显改善" |
| Q4 | 措施分层 | 措施跨短期/中期/长期，且至少一项工程控制/系统层面；每条有责任人与可验证完成标准 |
| Q5 | 重复闭环 | 重复率最高前三类有专项措施；重复判定按"相同方法（项目/平台+检项）+ 相同原因"分组 |
| Q6 | **GMP 框架嵌入**（7/19 审核唯一 0 分项） | 措施关联具体 SOP 编号；引用药典/ICH 条款（如 ChP 9205 实验室数据管理、ICH Q10）；关联已有 CAPA 编号；引用 ALCOA++ 说明台账记录要求 |

### 措施要求（占比前三 + 无措施合理性 + 人员操作归因）

- **占比前三的类型逐个下钻**：每类给出典型记录、涉及人员/项目、时间分布、该类现有措施与效果评价，并**逐一给出针对性措施**——不得只给一张笼统的 P1–P4 表
- **无措施项逐条判合理性**，分三档：可不采取措施（有依据，如已证实的偶发仪器波动 + 预防性维护）/ 部分合理 / 应采取措施而无（合规缺口）。**"无明确原因 + 无措施" = 必查项**，必须进入报告风险结论
- **源表结构缺失 ≠ 未采取措施**：某年 sheet 若**根本没有 CAPA 措施列**（实例：25-26 偏差的 25 年 sheet 13 列无 CAPA 列），该年的"无措施"是**源表结构缺失**，不可判为"未采取措施"——必须在报告 §0 口径声明写清，否则 GMP 出红项
- **人员操作类归因合理性**：对照详细原因检查是否把系统性问题（方法不稳健、文件不清晰）记到人头上；该类措施若只有培训且 6 个月内复发 → 判"归因不足、措施无效"
- **偶然异常占比**：确认率 ≥80% 为调查深度合格线；"无明确原因"占比同比扩大 = 恶化信号，必须单独成段

### 交付要求

报告末尾附「生成端自检结果」表（D1–D7 + Q1–Q6 逐项 ✅/🟡/🔴 + 不通过项的整改说明），随报告一起交付。**没有这张表的报告视为未完成。**

**交付物 = HTML，不是 md**：上表与全部章节必须落在**交互式 HTML**（ECharts + 数据质量说明 + 自检表）里才算交付；md 是中间稿。停在 md 不转 HTML = 漏交付，交付前按「报告正文撰写 → 交付物闸门」清单逐项核。唯一例外是用户明确只要 md。

## 扩展分析：无效测试台账分析

当数据源为"无效测试台账"（而非自检缺陷）时，列结构和指标体系不同，需切换分析模式。详见 `references/invalid-test-analysis-patterns.md`。

关键差异：
- **原因分类体系**：基础原因（仪器系统耗材/人员操作/偶然异常/文件/方法/无明确原因等）+ 详细原因（具体到操作失误/柱效下降/方法不适用等）
- **CAPA有效性衡量**：不是"是否整改"，而是"同一详细原因是否在6个月内重复发生"
- **重复发生率**：有措施记录中52%出现同一原因6个月内重复，说明CAPA体系有效性偏低
- **措施类型分类**：培训/SOP修订/硬件处理/经验分享/其他，不同类型对应不同效果

## 扩展分析模式：质量事件与检验压力的相关性

当用户问"质量事件增加是否与工作量相关"时，切换到 `references/workload-correlation-analysis.md`，**先取分母**（见「阶段 4 → 工作量数据接口」）。

**分析流程**：
1. 事件侧清洗与本文件阶段 0–1 一致；工作量侧取用户提供的数据或已有工作量报告
2. 按月份对齐事件数与检验量，计算事件率（事件/百工时 或 事件/检验批次）
3. 组合模式识别：
   - 高负荷低事件率 → 团队抗压能力强，但需关注疲劳累积
   - 低负荷高事件率 → 更可能是系统性因素（方法变更、人员变动、设备问题）
   - 事件类型分布不均（如 OOX 集中在包材组）→ 该方法/标准本身有问题
4. 结论表述：无分母时**不得**断言"正相关"；有分母时给出相关系数与样本量，并注明"相关不等于因果"

**范围边界**：工作量本身的测算（年度汇总口径、折算全年、人均负荷率基准、需配人数与人员缺口、弹性配置建议）属于**工作量线** `pharma-qc-workload-analysis`，不在本 skill 展开。

## 已知陷阱

> ⚠️ **时效告警（2026-09-25）**：以下 1–20 条多为 **25/26 三年台账的年份专属经验**（哪个 sheet 第几列、哪年缺哪个字段）。明年换数据源后会变成误导——**待办**：下一轮实际使用本 skill 后，把"经验"提炼成"方法"、年份细节下沉到 `references/column-mapping-guide.md`，本列表只留可迁移的判据。

1. **列结构不一致**：每年sheet的列排列可能不同，适配每张sheet
2. **责任班组的写法差异**：`原辅料+包材分析组` vs `原辅料+包材及水组` vs `原辅料组`，用包含匹配 `in` 而非精确匹配
3. **部分标注为"讨论项"**：有些记录不是硬缺陷而是待讨论，需区分"是否定义为缺陷"列
4. **年度同比的对齐**：25年可能含全年数据（1-12月），26年可能只有1-5月，需要先过滤再对比
5. **分类粒度不一致**：同类型的缺陷可能在25年是`记录-内容漏写`，24年是`记录-填写不全`，映射到统一分类体系
6. **uv安装依赖**：PEP 668限制，使用 `uv pip install openpyxl` 而非 `pip install`
8. **重复发生评价的粒度**：分析CAPA有效性时，不能仅按"基础原因+详细原因"全局匹配判定重复。**同一原因分类在不同检验方法下发生，不属于重复**（不同方法有不同操作环境和风险点）。必须按"检验方法（平台+项目）"分组后再匹配原因，否则会将无关的系统性问题误判为重复，或将真正的重复掩盖。详见 `references/invalid-test-analysis-patterns.md` 中的"方法级精确匹配"模式。
17. **严重性需从描述推断**：当前数据源无严重性分级字段，需从缺陷描述文本中通过关键词匹配推断（过期/数据完整性/追溯性→高；标识/记录→中；清洁/定置→低）。
18. **目标人员过滤（OOX/偏差/验证偏差）**：当用户指定一组相关人员需分析其质量事件时，需在解析每个sheet前先提取"报告人/发起人"字段，用包含匹配过滤。关键点：(1) 报告人常与日期混在同一单元格（如`杜x\n2025.10.22`或`杜x2026.01.27`），(2) 过滤后需检查哪些事件被剔除（打印SKIP日志），(3) 偏差文件的25年sheet中发起人列是col5，26年sheet是col3，(4) 验证偏差的发起人在"QC/姓名"格式中（如`QC/任金玲`），需用`in`匹配。
20. **OOE编号提取**：25年-4 sheet的OOE编号列全为0.0，需从描述文本中用`re.search(r'(OOE\d+)', desc)`提取；若无OOE编号，可用日期+序号构造临时ID如`OOE2xxxx`。
22. **本 skill 范围外——工作量数据自身的解析规则**（多数据区 header 行定位、年度汇总口径、折算全年）：归工作量线 `pharma-qc-workload-analysis`，本 skill 只做事件侧与相关性。
23. **人均工时基准需考虑非检验时间**：174h/人/月是理论最大值（21.75天×8h），实际 GMP 实验室需扣除培训、会议、CAPA 等非检验时间；比较事件率时若用理论基准会低估压力，必要时按 120–140h 讨论。
24. **事件率在小样本下失真**：当月工作量很低时（如 94h），事件率（事件/百工时）会被放大，必须结合绝对值解读，不能只看比率。
25. **房间名跨年变体未归一化**：跨年房间维度对比前必须归一化房间名。同一物理房间在不同年份 sheet 中可能用不同写法。不归一化会把"房间名变了"误判为"该房间清零"，跨年清零结论可能是假象。归一化规则：先打印全部唯一房间名人工确认映射，再用包含匹配（`in`）而非精确匹配；拿不准的映射留给用户确认，不要自行推断。
