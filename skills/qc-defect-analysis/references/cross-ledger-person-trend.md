# 多台账跨源人员维度分析（人员趋势）

> 2026-09-25 由 `oox-subset-deep-analysis` 归并而来（已归档）。适用：用户要求「各人员的变化趋势」，且已有多份分台账子集报告（各自已 GMP 审过）。

## 打法

1. **能引用就引用**：自检类人员数据直接引用既有自检分析 HTML 的 §5 责任人员表，**不重解析 xlsx**；
2. **必须直解的**：偏差三源 + 无效测试台账 → 逐源硬编码列号出人员级计数：
   - 无效测试：「发起人/时间」列是 `姓名+日期` 混合（`蒋xx2025.01.01`）→ 正则 `^(.*?)\d{4}\.(\d{2})\.\d{2}$` 提取姓名；空记录（基础原因/详细原因/CAPA/类型四列全空）→ 计入总数、剔除于有效统计、单列补录提示；无措施判定 = CAPA 列 ∈ {空, N/A, 无, /}。
   - 偏差：责任人取「发起人」列（25 年 sheet 无 CAPA 列；「责任部门」是部门代号，不能当个人）；验证偏差「发起人」是 `QC/姓名` 格式 `split('/')`；计算机化系统事件只有「报告人/日期」列（姓名可能带换行，须先归一）。
   - **OOX 台账源表无个人责任人字段**（责任部门 100% = QC 实验室）→ 人员表 OOX 列标 `—`，OOX 只进「整体趋势判断」段。
   - 名单外人员（如 CM 部门）计入该台账子集总数，但人员表标「非名单人员 N 件」、不并入 delta。
3. 汇总口径：每台账 25（全年）vs 26（截至 X 月）分列 + 四类合计 + 每人逐台账 delta。

## 人员级 delta 判读三型

| 型 | 特征 | 实例 |
|---|---|---|
| ① 总量恶化型 | 总量显著上升 | 邱xx 5→18 |
| ② 结构转移型 | 总量持平但台账间转移 | 桂xx 9→9 但无效测试 2→5；杜xx 5→5 向偏差类转移（含数据完整性未闭环项） |
| ③ 收敛型 | 明显下降 | 扎西aa 6→0、陈xx 8→3 |

②③ 型必须写明**问题源在哪类台账**；**收敛不彻底型**（如某人自检/偏差清零但无效测试 5→7）不能写成「整体收敛」。

## 跨台账共现弱点（整体分析的价值点）

同一弱点在多台账同时命中（实例：「4B 文件缺陷 + 有明确根因不起 CAPA」在偏差 D26022/D26037、无效测试 4 件不合理无措施、OOX 3 件文件类根因三处同时命中）→ 单独 callout，一句话指到系统性机制缺口（如 SOP 覆盖度审查缺失 + 处置习惯）。这是整体分析相对分台账报告的价值点。

## 出稿前一致性检查

- 每台账 25/26 分列数 vs 既有分台账子集报告数字逐一核对（对不上 = 解析口径变了）；
- 人员合计行逐列加总；
- 26 年各台账覆盖月数不一致（如偏差 1–9 月含 1 条补录中记录、其余 1–8 月）时必须写口径 callout；
- 每人解读文字与该行 delta 方向一致，并引用具体事件编号（`D26xxx` / `InA-QC-xxxx-xx`）供检索。
