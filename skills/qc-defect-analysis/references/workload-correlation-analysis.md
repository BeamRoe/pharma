# 工作量与质量事件相关性分析模式

## 触发条件

当用户提供包含检验工作量数据的Excel文件（含批次数量、检验项目数量、工时、人员配置等字段），并要求分析：
- 年度/半年度工作量对比
- 人均工作量与负荷率
- 人员配置缺口
- 质量事件与检验压力的相关性
- 工作量趋势预测

典型文件名模式：`*工作量*.xlsx`、`*质量事件*工作量*.xlsx`、`*检验*工作量*.xlsx`

## 数据源结构识别

### 典型结构

文件通常包含多个数据区域（非标准sheet结构）：
1. **年度汇总区**（顶部）：按物料类型（原材料/辅料/溶媒/气体/内包材/外包材/耗材）列出年度总批次、总项目、总工时
2. **类别汇总区**：2026上半年 vs 2025全年对比（批次/项目/工时）
3. **月度明细区**（底部）：按月+类别（原辅料/包材）列出批次、项目、工时、人员、各类质量事件

### 解析关键

```python
# 月度数据通常在文件末尾，header行包含中文列名
# 需先扫描所有行的第一个单元格，找到包含"月份"的行作为header
for i, row in enumerate(df.values):
    if row[0] == '月份':
        header_row = i
        break
monthly = df.iloc[header_row+1:, :].copy()
monthly.columns = df.iloc[header_row, :].values
```

### 类别映射

| 原始类型 | 归类 | 说明 |
|---------|------|------|
| 原材料 | 原辅料 | 化学成分、中间体等 |
| 辅料 | 原辅料 | 药用辅料 |
| 溶媒 | 原辅料 | 有机溶剂、水等 |
| 气体 | 原辅料 | 压缩空气、氮气等 |
| 耗材 | 原辅料 | 一次性耗材 |
| 内包材 | 包材 | 直接接触药品的包装材料 |
| 外包材 | 包材 | 外包装、标签等 |

## 分析流程

### Phase 1: 数据加载与清洗

1. 读取Excel，识别header行（包含"月份"的那一行）
2. 转换数值列：`pd.to_numeric(col, errors='coerce')`
3. 计算衍生列：`质量事件总数 = 无效测试 + OOX + 偏差 + 验证偏差 + CS事件`
4. 月份列清洗：`str.replace('月', '').astype(int)`

### Phase 2: 年度对比

```python
# 2026上半年 vs 2025全年
# 注意：2026 H1数据可能只覆盖1-N月（不一定是6个月）
h1_ratio = h1_value / annual_2025_value
projected_annual = h1_value * (12 / num_months_in_h1)  # 更精确的投影
yoy_change = (projected_annual - annual_2025_value) / annual_2025_value * 100
```

**关键指标**：
- H1/全年占比：判断工作量增长趋势
- 折算全年同比：判断年度间变化幅度
- 单批次检验复杂度：`检验项目数/批次数量`，判断是否单批工作量上升

### Phase 3: 人均工作量与负荷率

```python
std_hours = 174  # 21.75天 × 8小时/人/天
per_person_hours = total_hours / headcount
engagement_rate = per_person_hours / std_hours * 100
needed_headcount = np.ceil(total_hours / std_hours)
gap = needed_headcount - current_headcount
```

**负荷率解读**：
- <30%：严重闲置
- 30-60%：轻度负荷
- 60-80%：适中
- 80-100%：高负荷
- >100%：超负荷，需增加人员

### Phase 4: 质量事件与检验压力相关性

```python
# 事件率（每百工时的event数）
event_rate_per_100h = total_events / total_hours * 100

# 人均事件
events_per_person = total_events / headcount

# 相关性分析（至少需要6个月数据才可靠）
from scipy import stats  # 或手动计算Pearson
r = pearson(workload_metric, event_metric)
```

**关键洞察模式**：
1. **高负荷低事件率**：团队抗压能力强，但需关注疲劳累积
2. **低负荷高事件率**：可能存在系统性因素（方法变更、人员变动、设备问题）
3. **事件类型分布不均**：如OOX集中在某一组，提示该方法/标准有问题
4. **事件率与工作量无显著正相关**：当样本量足够时，事件更多取决于系统性因素而非绝对工作量

### Phase 5: 人员配置建议

```python
# 按月份计算所需人数
for month in months:
    needed = ceil(month_hours / std_hours)
    gap = needed - current_staff
    if gap > 0:
        suggest_hire(month, gap)
    elif gap < -1:
        suggest_release(month, abs(gap))
```

**弹性配置策略**：
- 识别高峰月份和低谷月份
- 建议最小/最大人员配置
- 考虑跨组调配可能性

## 关键发现模板

撰写分析结论时，按以下结构组织：

1. **工作量趋势**：H1 vs 全年对比，折算全年同比变化
2. **单批次复杂度变化**：项目/批次的趋势，判断检验深度是否增加
3. **人员负荷评估**：各组各月的负荷率，识别闲置和过载月份
4. **质量事件分布**：事件时间分布、类型分布、类别分布
5. **压力-事件相关性**：事件率与工作量/人均负荷的关系
6. **人员配置建议**：基于负荷率的最小/最大编制建议
7. **风险预警**：高负荷月、事件爆发月、系统性风险信号

## 已知陷阱

1. **数据覆盖月份不完整**：H1数据可能只覆盖1-5月（缺少6月），折算全年时需注明实际覆盖月数，不能简单×2
2. **2025全年数据来自汇总区**：需手动累加各物料类型的年度数据，不能直接从月度明细反推
3. **包材 vs 原辅料分类**：原始数据按物料细分（原材料/辅料/溶媒/气体/内包材/外包材/耗材），分析时需先归类为"原辅料"和"包材"两大组
4. **人均工时基准**：174h/人/月是理论最大值，实际GMP实验室需考虑培训、会议、CAPA等非检验时间，建议按120-140h/人/月作为更实际的基准
5. **事件率在小样本下失真**：当月工作量很低时（如5月94h），事件率会被放大，需结合绝对值解读
6. **CS事件罕见但重要**：变更控制事件极少发生（可能半年仅1起），一旦发生即提示系统性风险，需单独标注

## 与qc-defect-analysis的关系

本模式与 `qc-defect-analysis` 中的质量事件分析互补：
- `qc-defect-analysis`：聚焦缺陷/事件的根因分析和CAPA评估
- 本模式：聚焦工作量与事件的关联性分析，回答"检验压力大不大、人够不够、事件是否和工作量相关"

当用户同时提供工作量数据和缺陷/事件数据时，应结合两种模式综合分析。
