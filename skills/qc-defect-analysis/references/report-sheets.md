# 报表、报告结构与提示词模板

## 18-sheet 报表清单（pandas 输出，每分析一个sheet）
01_Data_Quality_Check / 02_Annual_Summary / 03_Monthly_Trend / 04_Record_Type_Pareto / 05_Department_Pareto / 06_Product_Pareto / 07_Process_Stage_Pareto / 08_Root_Cause_Category_Pareto / 09_Root_Cause_Subcategory_Pareto / 10_OOS_By_Test_Item / 11_OOS_By_Instrument / 12_Severity_Risk_Matrix / 13_Repeat_Events / 14_CAPA_Status / 15_CAPA_Overdue / 16_Long_Closure_Cycle / 17_Recommended_Focus_Areas / 18_Methodology

18_Methodology 是强制sheet：写统计逻辑、脚本版本、数据质量结果。Pareto sheet 必须含 数量/占比/累计占比 三列，Top3 累计占比是解读锚点。

## 14节报告结构
1. 回顾目的和范围  2. 数据来源和统计口径  3. 数据完整性和质量检查结果  4. 年度质量事件总体情况  5. 偏差趋势分析  6. OOS/OOT/异常测试专项分析  7. 根因 Pareto 分析  8. 重复事件和系统性问题分析  9. CAPA 执行和有效性回顾  10. 高风险问题清单  11. 年度重点改进方向  12. 建议措施和责任部门  13. 结论  14. 附录：数据清洗规则、脚本版本、图表清单

第3节数据质量章节是强制内容：缺失字段比例、未关闭记录数量、未分类根因数量、无CAPA关联记录数量、不能纳入趋势判断的数据限制。

## OOS/异常测试专项十维度
1. 检测项目  2. 样品类型  3. 仪器  4. 方法编号  5. 分析员  6. 实验室班次  7. 是否复测  8. 是否确认实验室错误  9. 是否确认产品/工艺原因  10. 是否无效检测
OOS 必须单独分析，不混入一般偏差。OOS 最终结论必须回到已批准的 OOS 调查报告，不能凭描述自行判定"实验室错误"或"产品不合格"。

## 重复事件三分类
- 完全重复：同一产品+同一工艺步骤+同一根因+同一问题描述
- 相似重复：不同产品/批次，但根因和问题模式相似（用相似文本聚类识别，不改变原始批准根因，标注需人工确认的归类）
- 系统性重复：不同表象指向同一质量系统缺陷（培训、SOP、维护、变更评估不足）
输出格式：主题 | 涉及记录号 | 可能系统问题。

## 主提示词模板（周期回顾项目启动用）
你是制药企业质量数据分析助手，用于辅助年度偏差、OOS、OOT 和实验室异常回顾。
工作边界：
1. 你不能替代 QA、QC、生产、质量负责人作最终 GMP 判断。
2. 你不能编造数据、根因、CAPA 或结论。
3. 所有统计数字必须来自输入数据或脚本输出。
4. 对自由文本归类只能作为建议，必须标注"待人工复核"。
5. 对 OOS/OOT 的最终原因和结论只能引用已批准调查报告。
6. 输出必须区分：数据事实、趋势观察、可能原因、建议措施、需人工确认事项。
请按以下步骤工作：
A. 检查数据字段是否完整。  B. 识别重复记录、缺失字段、异常日期、未关闭记录。  C. 生成数据清洗规则。  D. 生成可复现的 Python/SQL 分析脚本。  E. 输出年度趋势、Pareto、Top 10、风险矩阵、CAPA 有效性分析。  F. 生成年度质量回顾报告草稿。  G. 列出分析限制和需要人工确认的问题。

## 五层结论模板（报告解读段）
- 数据事实：[仅数字，来自输入表]
- 趋势观察：[峰值/上升/集中现象，结合生产批量、产品切换、人员变动、检验负荷]
- 可能原因：[必须带"可能"，不作确认表述]
- 建议措施：[按风险优先级排序，责任部门明确]
- 需人工确认：[根因分类与批准报告一致性、产量因素、CAPA覆盖度]
