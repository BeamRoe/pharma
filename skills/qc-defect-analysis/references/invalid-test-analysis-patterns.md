# 无效测试台账分析模式

## 数据源识别

当用户提供的Excel文件名包含"无效测试台账"或列结构包含以下字段时，使用此模式：
- 无效测试编号、类型（系统适用性不符合要求/实验中断/无效的运行与检测结果）
- 基础原因分类、详细原因分类
- 纠正预防措施、计划关闭日期、关闭人/关闭日期
- 组（理化组/微生物组/小分子组/免疫组等）

## 分析维度

### 1. 分类统计

**按类型**：系统适用性不符合要求/实验中断/无效的运行与检测结果
**按基础原因**：仪器系统耗材/人员操作/偶然异常/文件/方法/无明确原因/其他/试剂/试液/标准品/参比品/管理/操作环境
**按详细原因**：具体到操作细节（人员疏忽/色谱柱柱效下降/方法不稳健/仪器故障等）
**按组**：理化组/微生物组/小分子组/产品理化/

### 2. 根本原因确认率

```python
confirmed = 0  # 基础原因 != '无明确原因'
unclear = 0    # 基础原因 == '无明确原因'
```

**阈值**：已确认率应≥80%。低于此值说明调查深度不足。

**关键发现**：实践中"无明确原因"记录往往无措施（73/76条无措施），形成合规盲区。

### 3. CAPA有效性 — 重复发生率

**核心指标**：有纠正预防措施的记录中，**相同方法（项目/平台 + 检项）因相同原因**在 6 个月内是否再次发生。

> ⚠️ 分组键必须带**方法维度**（与 SKILL.md 陷阱 8 一致）：同一原因分类出现在不同检验方法下**不算重复**——不同方法有不同操作环境与风险点，全局匹配会把无关的系统性问题误判为重复，也会把真正的重复掩盖。7/19 审核把"检验方法+基础原因精确匹配"列为**亮点**，说明这个口径是被认可的。

```python
# 对每个 (方法, 详细原因) 组合，按日期排序，检查 6 个月内重复
for (method, detail), records in keyed_records.items():
    records.sort(key=lambda x: x['date'])
    for i in range(len(records)):
        for j in range(i+1, len(records)):
            diff = (records[j]['date'] - records[i]['date']).days
            if 0 < diff <= 180:
                repeat_count += 1   # 同一方法 + 同一原因 6 个月内重复
```

**方法字段的可得性**：本台账 26 年 `proj`（项目）列缺失率高（实测 15/16 行为 N/A）——此时必须降级为可用字段（检验项目/平台），并在报告中写明"可匹配 n=X，占 Y%"，**不得**在不可匹配字段上给"0 件重复"这类结论（见生成端自检 D4）。

**实践阈值**：重复率>30%说明CAPA体系形同虚设。实践中常见52%的重复率。

**按原因分类的重复率排序**（从高到低）：
- 人员疏忽：最高（培训类措施无效）
- 方法不稳健：高（SOP修订后仍复发）
- 色谱柱柱效下降：高（报废措施无预防性维护策略）
- 仪器故障/异常：中高
- 文件类：中

### 4. 措施类型与效果

| 措施类型 | 典型触发原因 | 效果评估 |
|---------|------------|---------|
| 培训 | 人员操作/疏忽 | ❌ 差，重复率最高 |
| 经验分享/复盘 | 人员操作 | ❌ 差，无实质改变 |
| 硬件处理（报废/维修） | 仪器系统耗材 | ⚠️ 短期有效，无预防策略 |
| SOP/方法修订 | 文件/方法 | ⚠️ 修订后仍复发 |
| 复核机制 | 人员操作 | 待验证 |

### 5. 年度对比

比较2025 vs 2026的原因结构变化：
- 哪些类别上升/下降
- "无明确原因"占比是否扩大（恶化信号）
- 措施覆盖率是否变化

### 6. 子团队对比

当需要聚焦特定人员或班组时：
```python
target_people = ['张三', '李四', ...]
mg_records = [r for r in all_records if any(p in r['person'] for p in target_people)]
```

对比子团队 vs 全组的差异：
- 子团队的原因分布与全组的偏离度
- 子团队是否有独特的系统性问题

## 关键发现模板

撰写分析结论时的结构：

1. **结构性发现**：原因分布与全组的差异（±5个百分点以上标为显著）
2. **趋势性发现**：年度间原因结构的变化方向
3. **有效性发现**：措施类型与重复率的对应关系
4. **合规风险**：无明确原因且无措施的比例
5. **人员风险**：高频人员的独特问题模式

## OOX/OOE/OOT/偏差/验证偏差 数据源模式

当数据源为 `质量事件/` 目录下的 `oox.xlsx`、`偏差.xlsx`、`验证偏差.xlsx` 时，使用此模式。

**核心特征**：
- 多sheet结构，各sheet列索引完全不同，必须逐sheet确认映射
- ID可能缺失（OOE的编号列全为`0.0`），需从描述中regex提取
- 合并单元格导致数据溢出到相邻列（如`25年-3`最后一行报告人/日期/编号/部门/检项挤在col0）
- 不同sheet可能有重复记录（如`25年-1`和`25年-2`都含00Sxxx），需去重
- 必须包含OOE（Observation of Exception），不可遗漏

**根因分类体系**（适用于所有质量事件类型）：
| 大类 | 关键词 | 示例 |
|------|--------|------|
| 人员(Man) | 人员/意识/未核对/误吸/混淆/未执行 | 分析员未核对样品信息 |
| 清洁方法/流程 | 清洁/CIP/清洗/消毒/冲洗/残留/网带/POM/乙醇喷洒 | 清洁方法无法覆盖 |
| 文件/方法 | 文件/SOP/规程/描述不准确/规定不完善/细节/未固定 | 检验文件规定不完善 |
| 环境 | 乙醇/酒精/污染/交叉/环境/存放/碱残留/地漏 | 样品存放靠近乙醇喷壶 |
| 器具/材料 | 滴定杯/器具/容器/划痕/管路/气泡/手阀/超声波/容量瓶 | 容量瓶内壁划痕 |
| 设备 | 设备/仪器/烘箱/泵 | 烘箱温度漂移 |
| 其他 | 无法归类 | 原因未填写 |

**CAPA有效性评估**：
- 培训/SOP修订类：当同类检项在6-12个月内再次发生，评估为"无效"
- 工程控制（硬件升级/物理隔离/防呆设计）：评估为"有效"
- 需区分"用户标记重复"和"自动检测跨年度重复"

**HTML报告要求**：
- 必须包含：概览数字卡片、月度趋势柱状图、根因分类饼图、部门×根因矩阵、重复事件详情表、关键发现与建议
- 使用ECharts（CDN引入），每个图表独立div
- 分块写入策略：Part1（概览+趋势），Part2（重复+深度分析），Part3（根因+严重性+建议）
