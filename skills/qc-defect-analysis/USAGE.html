qc-defect-analysis 使用说明

版本 V1.0 ｜ 2026-09-28 ｜ 给使用者的操作手册（SKILL.md 是 AI 内部流程，本文件是你调起、喂数据、读结果的入口）

一、这个 skill 能干什么

把 QC 自检 / 质量事件的台账 Excel，变成「分类 + 趋势 + 根因 + CAPA + 自检」的完整分析报告（HTML + 自检表）。

覆盖数据源

数据源说明触发词举例
QC 自检缺陷台账内部审计发现的记录/标识/管理/设备类缺陷“对自检情况进行趋势分析”
OOX（OOS/OOT/OOE）检测结果异常“OOS 回顾”
偏差 / 验证偏差工艺或验证偏离“偏差周期对比”
无效测试台账实验室运行中断/系统适用性失败“无效测试分析”
不覆盖：工作量本身的人力测算（人均负荷、人员缺口、弹性配置）——走工作量线 pharma-qc-workload-analysis。本 skill 只做「质量事件与检验压力的相关性」。

二、怎么调起

直接说一句含触发词的话即可：

  • “对 QC自检汇总.xlsx 做趋势分析，聚焦原辅料+包材及水分析组”
  • “做 25 vs 26 年 OOS 同比回顾”
  • “分析无效测试台账，按班组分类”
关键：任务命中触发词后，AI 第一步必须 skill_view 加载本 skill 正文，不能凭记忆直接开跑（AGENTS.md 已立强制规则）。

三、喂数据前你要准备的 3 件事

#你要给的为什么
1台账 Excel（放 <工作目录>/<类型>/ 下）数据源。多 sheet / 跨年 sheet 都行
2聚焦班组（如“原辅料+包材及水分析组”）不指定则全组分析，数据量大
3归一化分母（生产批次数 / 检验批次数 / 在岗人数 / 加班调休工时）没有则趋势判断降级为绝对数，不可与产量变化解耦

分母取数顺序（skill 写死的三级）

  1. 先向你索取 — 拿到什么用什么，不臆测
  2. 或从已有报告/台账取数（工作量趋势报告、台账）
  3. 都拿不到 → 降级为绝对数，并显式标注“归一化所需分母缺失”
没有分母不能自行断言“事件增加与工作量正相关”——这是提问式分析步骤，不是结论。

四、你会拿到什么（交付物）

交付物格式位置
分析报告正文Markdown<工作目录>/<类型>/趋势分析/
交互式 HTML 报告HTML（ECharts + KPI 卡片 + 自检表）同上 .html
修复副本（源 xlsx 打不开时）xlsx/tmp/ 或数据源旁

HTML 报告固定包含

  • 概览数字卡片（KPI）
  • 月度趋势柱状图 / 根因分类饼图 / 部门×根因矩阵
  • 重复事件详情
  • 关键发现与建议
  • 生成端自检表（D1–D7 + Q1–Q6 逐项 ✅/🟡/🔴）— 没有这张表的报告视为未完成

五、报告里的「自检表」怎么看

每张报告末尾附 D1–D7（数据正确性）+ Q1–Q6（分析质量）自检：

标记含义
✅ 通过该项满足
🟡 待确认需你人工判断或补数据（如 Q2 根因深度、Q6 GMP 框架嵌入）
🔴 不通过该项有缺陷，报告已写明整改方向
你作为使用者要做的：看 🟡/🔴 项，决定是否补数据/下版本修订。🟡 通常是"数据缺失"或"需确认归因"，不是 AI 算错。

六、源文件打不开（xlsx 损坏）怎么办

skill 已内置关 0（文件可访问性检查）。若你的 xlsx 是 WPS 导出、GUID 损坏或空 ZIP：

  • 原件不要动，AI 会自动生成修复副本（/tmp/xxx_fixed.xlsx）
  • 修复方法：删 customWorkbookViews 元素 + 清理 definedName GUID 前缀
  • 修复成功才进后续解析；失败会直说"无法读取"，不编造数据

七、数据脱敏提醒

喂给 AI 的台账里，人名/批号/时限可能是占位符（空 / xxx / 随意填）：

  • 占位符既不是内容也不是缺口：不当真值、不据此判"已具备"、不因它阻塞流程
  • AI 会照实记录 + 显式标注"待回填"，不会替你脑补
