# 质量事件流程 · S2b 调查报告（根本原因调查）

> **流程位置**：S2 后半。上游 = S2a 方案 + 执行数据；下游 = S3 风险评估 / S4 CAPA / S5 自检与交付闸门。
> **直接成文**：本步产出即为可送审的报告终稿体裁（不另设"成文"环节）。
> **适用**：OOX / 偏差 / 无效测试。**缺陷不走本链**（走回复报告 8 段线）。
> **闸门**：报告**审核通过才能往后走**；未通过按意见修订 V2.0。

## 一、本步做什么

把方案执行结果整理成报告，**给出根本原因、风险/影响评估与 CAPA**——这三项进报告后，S3/S4 可标注「见报告」。

## 二、输入

- `02_investigation_plan_V1.0.md`（含审核意见与放行记录）
- 实验数据、图谱、记录编号与页码
- S1 的 `01_initial_assessment.md`（结论段可引用）
- **可选：体系维度方向扫描**（`pharma-gmp-gap-scan` 的 12 维输出）——**仅作方向与待验证假设引用，不作为根因判定依据**（见该 skill 「在质量事件链中的挂点」）；**一旦引用，须在报告中对 `state = suspect` 的方向逐条交代已排查结论**（S5 会以此检查；`possible`/`not_indicated` 无需交代）

## 三、体裁：目的 / 范围 / 内容

> **节号非强制（2026-09-25 实测修正）**：下文的 3.1–3.5 与 4–7 是**要素清单**，不是固定节号——可按顶层单列，也可嵌在 §3 内容下（实例：真实 123456 报告用 3.2.4 根本原因判定 / 3.3 调查结论 / 3.4 影响评估 / 3.5 预防整改措施）。**要素齐 = 结构完整。**

### 1 目的

> 〔起止日期〕，〔人员〕根据〔事件编号〕调查方案〔及阶段性调查报告编号〕，对导致〔事件〕的可能原因进行了系统性调查。调查已结束，出具本报告，对调查结果进行整理与分析，评估结论并给出该〔事件编号〕的〔根本原因 / 最可能原因〕。

**要点**：一次实验定不下来、经过多轮迭代的，目的段要一并引用**阶段性调查报告编号**；只写"最可能原因"时，报告必须交得出"为什么不能唯一确定"的依据。

### 2 范围

> 针对〔事件编号〕调查的总结、分析、评估与报告。

### 3 内容

**3.1 首次调查方案执行与结果**

日期 + 人员 + 按方案做了什么 + 结果 + **与预期是否一致**；不一致时写明方案预设情形的对照结论（"与调查方案中预设的『……』情形相符"）。

**3.2 进一步调查**（迭代，按轮次分节）

每轮：日期 / 依据（上轮报告编号）/ 做法 / 数据 / 与预期的差异 / 本轮能否定性。**数据不足以定性时如实写"仅依靠该组数据无法确定原因"**，不硬推结论。

**候选原因被新证据推翻/坐实时（2026-09-26 补，本会话实测）**：

S1 给的是"候选原因清单 + 方向"，S2 实验数据可能**推翻 S1 的某候选**（如 S1 主查 PAA 残留，但 S2 厂家对照证"旧厂家无峰 + 新厂家留样有峰" → PAA 残留共因排除、厂家变更本征单杂坐实）。此时 S2b 报告须：
- **如实写"候选 X 被排除，依据 = S2 第 N 组实验/对照 Y"**，不得让 S1 的主查方向与 S2 实际证据矛盾却不自述
- **排除理由要指到具体证据**（"旧厂家同期无该峰"是排除"残留共因"的关键——残留若为前处理引入则与厂家无关、新旧厂家都该有；实际旧厂家无 → 排除）
- **不得把"未执行"的实验 2/3 写成"没必要"（消极辩护）**——若 S2 因根因已收口而未做完全部方案实验，S2b §3.2 须**写明未做理由 + 是否影响根因判定**（"实验 2 加标未做，因厂家对照已收口候选 2，加标只能重复验证已被排除的候选 1，不影响根因"），不得省略
- **GC-MS 定归属失败（未定归属）不阻塞根因判定**：当厂家对照/留样等**替代证据链已足以定根因**（如"旧厂家无 + 新厂家有"→ 厂家变更引入单杂）时，GC-MS 归属未定**不阻塞根因收口**，S2b 须写"根因判定不依赖具体化学归属，归属为后续第三方/补谱库问题（C2 纠正措施）"。**禁止**因 GC-MS 失败就把根因判"无法确定"——只要替代证据链闭合，根因仍可定。
- **收口强度如实标**：根因到"最可能原因（厂家变更带入本征单杂，具体归属未定）"而非"唯一确定"，写清"为什么不能唯一确定"（归属未定）的依据即可，这是 S2b skill 允许的

**3.3 数据汇总**

表格汇总各轮各组的实测值、平均值、与限度的关系；必要时附电极电位/斜率等辅助数据。

**3.4 分析与判定**

- 对照方案预设情形逐条落位
- 数据无统一规律、无法唯一归因时，写**多重因素共同作用**并分别说明各因素的作用路径
- 明确写出：已排除什么、保留了什么、还有什么未定

**3.5 现行文件体系中的管理断点**（单列一节；当根本原因触及文件/机制层时必写）

写明现行文件的真实规定（引用条款原文与版本）→ 指出**断点**：哪份文件规定了什么、哪份文件没有把要求串起来、操作者为何难以识别关键控制点 → 由此支撑"系统原因"的判定。

**4 根本原因**

- 直接原因（物质/现象层，含机理）与根本原因（文件/机制层）**分开写**，主语必须是不同东西（R2 纪律）
- 每条写明**依据**：哪一轮实验、哪组数据、哪个记录编号支持（无依据的判断不许写）
- 根因深度按 **J1 判据**定终点：**先判控制点归属层**（原则/流程/机制类→属上位；具体操作/单点类→属本环节），**再判该层缺口性质**（缺/断/冲突）。归属本环节 → L3 补本环节控制点，不上溯、不需取证上位文件；归属上位 → 上溯并取上位文件编号 + 条款原文为证；归属上位但上位已覆盖 → 停 L3。同层同类控制点在 ≥2 处独立重复缺失 → 升级。输出判据调用记录，终点由审核人决断（细则见 `pharma-defect-response` J1 节 + 编排器 `references/gate_checklist.md`）；**原因识别的推理骨架与六步闸门**见 `pharma-qe-s1-initial-triage/references/analysis-method.md`（引用不复制）

**5 风险/影响评估**

- 落点按 **J2 判据**：落点句主语 = 缺陷/质疑对象，不外推未被质疑的对象
- 核实范围按 **J3 判据**：范围 = 质疑路径的边界；路径外项一句话说明"不在质疑路径上，故未排查"
- 禁令："影响可忽略/风险较低"等减责表述；"默认合规/推定合格"等消极辩护
- 涉及数据可靠性的，附 ALCOA+ 属性逐项判断

**影响评估：定量桥接优先于定性方向（2026-09-28 补，标准筛 D26051 实测）**：当用户回填了定量影响证据（表面积/浸出物换算、与滴定估读误差的比对、法定标准范围对照等）时，**必须按用户给的定量结论写，不得保留 AI 默认的保守定性（"假阴性不得排除""需复验"）**。判据：① 影响段先写"偏倚方向 + 幅度"，幅度有定量桥接（偏差→中间量→结果指标→与接受标准/读数误差比对）时，落到"影响可忽略/无需复验"，而非停在"不得排除"；② 法定/药典范围对照（如孔径虽超内部工艺允差但仍在药典范围）属影响评估的独立论据，须单列，不与"超内部允差"混判；③ 用户回填的定量结论推翻 AI 初稿定性时，**旧定性必须从正文删净**（grep 旧措辞 = 0），只留新结论，不得两处并存。**为什么**：保守定性（"不得排除""需复验"）是减责式兜底，一旦有定量证据支撑"无实质影响"，留着保守措辞 = 报告自相矛盾，S6/GMP 审核必打回。

**历史数据回溯（根因落在方法／标准／仪器／数据类时必写；2026-09-25 补）**

- 给出**时间窗与批次范围**：方法／标准类问题的起点 ＝ **该方法／标准生效的时点**（不是“上一次确认合格”），终点 ＝ 方法被纠正并确认；范围须列纳入与排除（含排除理由）
- 给出**结论三选一**：可靠 / 需复验 / 无法判定；**不得默认合规**
- 判定前提（关键逻辑）：先问「事件发生时体系有没有**当场抓住**它的手段」——没有手段，历批数据再漂亮也**不能自证**，结论只能是“需复验 / 无法判定”
- 给出**偏倚方向**：偏高 → 假阳性（合格判不合格）；偏低／被低估 → **假阴性**（不得排除，涉患者安全）
- **落地归属**：留样复测 / 年度质量回顾确认 → **QMS 年度质量回顾与稳定性线**（本报告只出结论，不承担执行）
- 定量评估（控制图 / 置换检验 / 效应量）交 `pharma-data-integrity-assessment`，引用其结论即可

**6 纠正与预防措施（CAPA）**

- **两分（缺一不可）**：**纠正 → 针对事件本身**（消除/隔离已知影响，挂**事件现象**）；**预防 → 针对根本原因**（防止再发生，挂**根本原因**）。每条措施标注 (纠正)/(预防) 并挂住对应依据
- 表格：序号 / **类别（纠正/预防）** / 措施内容 / 责任人 / 完成时限 / **交付物**
- 禁止"加强培训/提高意识"这类无交付物措施
- 分短期（纠正）与中长期（预防，含系统层/工程层）
- 附**措施有效性验证计划**：序号 / 验证方法 / 验证时点 / 判定标准（须量化）

**7 结论与待核实项**

一段话收口（查了什么→查到什么→根本原因是什么→影响如何→如何处置），再列待核实/待批准项。

> **审计应对（可选，缺陷线）**：需要应对检查员追问时，见 `pharma-defect-response/references/audit-response.md`（检查员五类追问 + 应对原则 + 与报告段落的对应关系）。

## 四、判据预检与留痕

判据文件在 `pharma-defect-response/references/criteria.md`（单一存放处，引用不复制）：

- **J1 根因深度**：① 控制点归属层（三问：原则/流程 vs 具体操作；体系惯例落点；换仪器/方法是否仍成立）② 该层缺口性质（缺/断/冲突）③ 归宿：本环节→L3 不上溯；上位→上溯 + 取上位文件编号与条款原文；上位已覆盖→停 L3 ④ 同层同类 ≥2 处独立重复缺失→强制升级（跨层复制不算）
- **J2 风险落点**：落点主语 = 风险点/质疑对象；未质疑对象不外推
- **J3 核实范围**：范围 = 质疑路径的边界，非批次全覆盖；路径外一句话说明不排查理由

每次调用写 `_meta/judgment_trace.yaml`（判据分支 + 参照案例 + 升级标记 + 待审核人决断项）。

## 五、成文体裁（R0–R6 泛化 · 表格准入 · 脱表阅读）

> **规则单一存放处**：`pharma-report-narrative`（R0–R6 泛化 + 表格准入三规则 + 脱表阅读关 + 转换边界）。本节只写本步的用法。

**起草时**按 R0–R6 写；**定稿前**过「脱表阅读关」（硬闸门；不过回本步重写）。

- **表格准入**：数据/参数/对照/措施要素 → 留表；**因果推理、排除逻辑、结论判断 → 必须成句**。判据：遮住表，正文能否读懂“为什么”。
- **叙述先行**：每节「做了什么 → 看到什么（数据表紧随） → 说明什么（『因此…』收口）」。
- **R0 场景还原段**：正文第一段先讲该检验环节**实际怎么运作**（直接由 `01e_timeline.md` 改写），不先下判断。
- **R4 风险段四拍**：后果推演 → 逐项排除 → 落点句主语=质疑对象（§5）→ 处置闭环。
- **R5 措施=根因镜像**：每条 CAPA 回溯到一条根因（§6）。
- 基本纪律（详见该 skill）：按时间轴叙述、因果分层主语切换、正文禁内部编号与元术语（保留 GMP 领域术语）、段间用“综合以上/基于上述/因此”承接。

## 六、产出与闸门

- 产出：`03_investigation_report_V1.0.md`（正文 + 编制/审核/批准签署栏），附件与 `_meta/`（judgment_trace、事实引用索引、待补项）外置
- 闸门：**报告审核通过 → 才能进入后续节点**
- **审核意见必须落盘（2026-09-27 补）**：`03b_report_review.md` 独立成文件（8 维评分 + 红/黄项 + 修订对照 + 签字栏）。**只在对话里出的审核意见不算审核**——实测（2026-09-26 浊度检测仪）：审核内容先写在对话中，直到 GMP 终审指出「引用了未落盘文件」才补，构成审计断点。
- **版本一致性（2026-09-27 补）**：修订一律在**副本**上做；副本**文件名的版本号须与文内版本号一致**；下游文件（`03b`/`03d`/`06_selfcheck`/`07_final_review`）引用的版本号须同步为当前版本。任不一致 = S5 版本一致性检查不过。
- **上游结论变更时（2026-09-27 补）**：S1 出口或方案在执行中途变更 → 先按 S1 skill §八之三 做传播处置（列受影响产物 + 逐条处置），再定稿。
- 后续：S3 风险评估、S4 CAPA 若本报告已含对应内容 → **标注「见报告 §5 / §6」**；S5 做自检与交付闸门

## 六之二、S1 方向处置段（2026-09-27 补，必写）

S2b 报告必须含一段「**S1 方向处置**」：S1 提出的**每个方向/可疑点**逐条交代去向——

| 列 | 内容 |
|---|---|
| S1 方向 | 引用 `01_initial_assessment.md` 的原表述 |
| 处置 | **排除** / **坐实** / 待查 |
| 依据 | 指向实验数据、图谱、记录编号 |

**为什么必写**：S1 的方向允许被 S2 推翻（实战：某表面活性剂一案 S1 判“PAA/异丙醇前处理引入”，S2 由“留样重分取有峰 + 旧厂家同期无峰”排除并改判“新厂家本征单杂”）。若不写这一段，审计只看到“结论变了”、看不到推演过程，等同**结论无依据**。

## 六之三、根因段的对象纪律（2026-09-27 补）

**根因主语 = 引入来源与机制**（变更带入 / 前处理引入 / 操作扰动 / 体系缺口…）；**物质/杂质的身份（归属、结构、毒理）属影响评估**——不得把“定出身份”当根因顶点。
身份未定 → 写入“缺口 + 影响评估待办”，并显式写“**不阻塞根因终点**”。依据：`pharma-defect-response/references/criteria.md` J1 配套纪律。

## 七、不做清单

不做 S1 的排查（引用）、不出调查方案（S2a 的事）、不做缺陷回复报告（8 段线）、不定级（S3）、不对外发布。

## 八、已知陷阱

1. **只写"最可能原因"却不给"为什么不能唯一确定"的依据**
2. **结果与预期不一致时直接跳到结论**：应如实写"数据无法确定原因，需进一步调查"并给下一轮方案
3. **风险段落点外推未质疑对象**（违反 J2）
4. **核实范围铺成批次/记录全覆盖**（违反 J3）
5. **CAPA 无交付物**（"加强培训"式措施）
6. **把内部编号与元术语写进正文**
7. **直接原因与根本原因主语相同**（没有分层，等于只有一个原因）
8. **结论无依据链**：每条判定都要能指到实验轮次与记录编号
9. **审核意见不落盘**：把审核意见写在对话里、口头说「审核通过」就往下走 → 审计断点（见 §六）。
10. **版本不同步**：patch 进同名文件后忘改名 / 改版本号；下游文件仍引用旧版本（实测两案均有：文件名 V1.0 而文内已是 V1.1；交付物 V3.0 而 `06`/`07` 写 V2.0）。
11. **带缺推进时把暂定结论写成定稿口吻**（2026-09-28 实测）：取数缺口未回填时，报告各结论须**逐处**标「暂定」+ 解除条件（A 类回填后复核升级），根因段须显式写「证据断点在哪」（如「H4 未排除，因标准颗粒有效期未取证」），影响段历史数据判「无法判定」而非「需复验/可信」。缺任一降级标注 = 把未坐实当坐实，S6 必打回。
12. **用户回填定量证据/处置方案后，仍保留 AI 默认保守定性**（2026-09-28 实测）：用户给出定量桥接（表面积→浸出物→滴定估读误差）、法定范围对照、处置颗粒度（接受校准结果、允差上限调 X%、某规格改半年校准、某规格只首校）后，AI 须**按用户结论改写**影响评估与 CAPA，**不得沿用早先的"假阴性不得排除/需复验/停用替代"兜底措辞**——用户回填的处置常比 AI 默认的"停用+周期复评"更贴合现场实务，AI 只补不删、以用户回填为准。旧保守措辞 grep 删净，只留新结论；处置建议也吸收用户给的规格级颗粒度（如 0.5mm 磨损 5%→改半年校准），不得停留在通用"缩短周期"。
13. **报告内嵌用户材料时，节号必须重排为报告自身节号**（2026-09-28 实测）：用户回填材料自带节号（如"4.1/4.2/4.3"），嵌入报告某节（如 §3.7 影响评估）时改标为报告内节号（§3.7.1/3.7.2/3.7.3），用户原节号仅以「（用户材料标注 §4.x）」括注保留；下游 04/05/_meta 引用同步用报告内节号，否则全目录出现两套 §4.x 冲突。改完 grep 全目录 `§4\.` 确认无裸引用。
