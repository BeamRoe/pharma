# GMP 差距扫描

> 定位：**事件的 X 光片，不是诊断书。**
> 本技能只做一件事——把一段自然语言事件描述，映射到 GMP 体系维度上，指出"哪些体系环节可能没长好"。
> 它**不**判定根本原因，**不**计算风险等级（那是 `pharma-qe-s3-risk-assessment` 的活）。

## 在质量事件链中的挂点（2026-09-25 定）

**挂点：S1（初步调查）之后 / S2b（调查报告）之前**——作为**体系维度**的补充扫描（S1 的 Ⅰa/Ⅰb 覆盖**操作维度**：人/机/料/法/环/样品/取样）。

**硬约束（用户裁定）**：

- **本 skill 只给方向、不给结论**（铁律 1），12 维输出**不得作为根因识别与根因判定的依据**
- **不得充当"根因识别判断"步骤**（在任何节点，含 S5）——根因识别由 **S1 逐项排查 + S2b 实验证实**承担，本 skill 只回答"还有哪些体系环节可能没长好"；**作为 S5 审核依据的限定用法见下条**（禁止的是"当根因识别"，不是"当审核依据"）
- 下游引用本 skill 产物时，引用的是 `findings`/`hypotheses_to_verify`（方向与待验证假设），**不能引用为根因结论**
- **作为审核依据的限定用法（2026-09-25 方案 A）**：S5 自检会检查 **`state = suspect`** 的维度在报告中是否被交代；**`possible`/`not_indicated` 不作检查项，不逐维打勾**（枚举视野不得抬为义务）
- 全部输出可归档为调查记录的“初步评估/头脑风暴”附件（与治理层声明一致）

## 铁律

1. **只给方向，不给结论。** 每条差距表述为"需核查……是否……"，禁止写成"根因是……"。
2. **没有证据就没有条目。** 事件描述里读不出来的东西，写进 `hypotheses_to_verify`（待验证假设），不写进 `findings`。
3. **宁可多列一个维度，不要漏掉一个。** 漏检成本远高于误报成本——这是筛选型工具，不是判定型工具。
4. **不编造条款。** 引用法规必须带条款号与版本；检索不到就写"未定位到具体条款，建议人工核对"。

## 何时使用 / 不使用

**使用**：偏差/投诉/召回/OOS/OOT/自检/外审发现的**初始描述阶段**，用来快速打开调查视野。

**不使用**：
- ❌ 事件已进入根因确认阶段 → 本技能价值下降，直接做 CAPA
- ❌ 需要评估历史批次数据是否仍可信 → `pharma-data-integrity-assessment`
- ❌ 需要给偏差定级 → `pharma-qe-s3-risk-assessment`
- ❌ 输入少于 **MVIS** → 先追问

**最小可用输入集（MVIS）**：
`发生了什么（现象）` + `在哪发生（区域/系统/工序）` + `怎么发现的（自检/QC检验/客户投诉/检查）`
三者缺任一，先输出 `gaps` 并追问，禁止开扫。

## 输入契约

| 字段 | 必填 | 类型 | 说明 | 缺失策略 |
|---|---|---|---|---|
| event_description | ✅ | text | 事件原文，越长越好，保留原始措辞 | 拒绝 |
| discovery_source | ✅ | enum | 自检/QC检验/生产现场/客户投诉/监管检查/供应商 | 追问 |
| area | ✅ | string | 区域、系统或工序 | 追问 |
| product_involved | 选填 | string | 品名+批号 | 记为 gap |
| timing | 选填 | date/period | 发生时间/发现时间/持续时长 | 记为 gap |
| prior_events | 选填 | text[] | 是否重复发生 | 记为 gap，重复发生会抬升严重度 |

## 扫描维度（12 维固定清单）

**每次必扫全部 12 维，不允许只扫"看起来相关"的。** 系统性缺陷往往藏在你以为无关的维度里。

| # | 维度 | 典型探针 |
|---|---|---|
| D01 | 人员与培训 | 操作是否依赖个人经验？培训是否覆盖该异常情形？ |
| D02 | 文件与记录 | SOP 是否有该情形的规定？记录设计是否允许如实填写？ |
| D03 | 数据完整性 | 数据是否同步记录？有无修改/补录/誊抄空间？审计追踪是否启用？ |
| D04 | 变更控制 | 事发前是否存在已实施变更（设备/物料/工艺/软件/人员）？ |
| D05 | 设备与设施 | 维护、校准、确认状态；是否有同类历史故障？ |
| D06 | 物料与供应商 | 物料变更、供应商变更、储存条件偏离？ |
| D07 | 工艺与验证 | 工艺验证状态、参数边界、是否处于已验证范围内？ |
| D08 | 环境监测 | 洁净度、压差、温湿度、微生物趋势？ |
| D09 | 实验室控制 | OOS/OOT 处理流程、方法适用性、标准品/试剂管理？ |
| D10 | 偏差与 CAPA 体系 | 是否为重复事件？既往 CAPA 是否真的闭环？ |
| D11 | 质量风险管理 | 是否做过该环节的风险评估？FMEA 是否覆盖？ |
| D12 | 管理层与质量文化 | 是否存在排产压力、报告链不畅、资源不足？ |

## 判定逻辑

对每一维输出三态之一，并给出该维度的**探针问题**：

```yaml
- dimension: D03 数据完整性
  state: suspect          # suspect | possible | not_indicated
  severity_hint: P1       # P1 建议优先查 / P2 建议查 / P3 可暂缓
  probe: "核查该工序的数据是否为同步原始记录，审计追踪是否开启并复核过"
  why: "事件描述中出现'事后补录'表述"     # ★ 必须引用原文片段
  evidence_ref: "原文第2段：'……'"
```

**状态定义（带锚点）**：
- `suspect`：事件描述中**有直接措辞指向**该维度 → 必须引用原文片段
- `possible`：该维度是此类事件的**常见关联面**，描述未提及但不能排除
- `not_indicated`：描述明确排除或未涉及，且无合理关联路径

**严重度提示规则**：
- `suspect` + 涉及患者安全/数据完整性 → P1
- `suspect` + 其他 → P2
- `possible` → P2（若维度属 D03/D04/D10 则升 P1，这三维是系统性缺陷高发区）
- `not_indicated` → P3

## 输出契约

```yaml
result:
  skill: pharma-gmp-gap-scan
  version: "1.0.0"
  generated_at: <ISO8601>
  input_echo: { area, discovery_source, description_length }
  scan_coverage: 12          # 必须恒为 12，证明全维度扫过
  findings:
    - id: GAP-001
      dimension: D03 数据完整性
      state: suspect
      severity_hint: P1
      probe: <可执行的核查动作>
      why: <原因>
      evidence_ref: <原文引用>
      confidence: medium
  hypotheses_to_verify:      # 无直接证据但值得查
    - dimension: D04 变更控制
      question: "事发前 6 个月内本区域是否有已实施变更？"
  gaps:                      # 信息缺口
    - "未提供发生时间，无法判断是否与某次变更时间窗重合"
  suggested_next_skills:
    - pharma-qe-s3-risk-assessment
    - pharma-data-integrity-assessment   # 仅当 D03 为 suspect 时列出
  confidence_overall: medium
  human_review_required: true
```

## 治理层

- 输出末尾固定附加：**"本结果为调查方向提示，不构成根本原因结论，需由跨部门调查组现场核实后确认。"**
- 禁止输出"根本原因很可能是……"这类表述。
- 若 `suspect` 条目 = 0 且 `possible` 条目 ≤ 2，显式提示"该事件可能为孤立偶发，但仍需按偏差流程完成调查"——避免给出"没问题"的错觉。
- 全部输出可归档为偏差调查记录的"初步评估/头脑风暴"附件。
