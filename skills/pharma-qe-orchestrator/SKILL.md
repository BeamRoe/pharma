# 质量事件主链编排器（S0–S6）

> **路由判据（2026-09-25 补，防漏接）**：凡输入描述的是「**某次检测结果 / 图谱 / 数据异常，或与标准、典型图谱、趋势不符**」，**无论用户是否使用“偏差 / OOS / OOE / 无效测试”这类术语，一律从本链 S0 进入**。具体：
> - 只给现象、未给六要素 → **S0 追问**（不得跳到 S1/S3）
> - **不得直接进 S1 初步调查、S3 风险评估或审核端 skill**
> - `oos-investigation-review` 是**审核端**（只在“已有报告要审”时用），**不是事件入口**
> - `pharma-gmp-gap-scan` 是**挂点**（S1 后 / S2b 前），**不是事件入口**
> - 旧 `pharma-deviation-management` 已于 2026-09-25 **归档**（`.archive/`），其编排职责**已全部并入本编排器**；任何指向它的引用以本 skill 为准

> 定位：**D 型编排层——它自己不产生结论，它决定“该让谁产生结论”。**
> 内部实现 = 一张状态机 + 一张节点调用表 + 一组分支/跳过判据 + 一组人工闸门 + 产物树与留痕。
> **单入口分流**：`pharma-qe-s0-event-intake` 按事件类型分流——**缺陷 → 缺陷线**（`pharma-defect-response` 8 段，无方案环节）；**OOX／偏差／无效测试 → 本链**。

## 一、状态机

```
S0 登记（六要素）
  │
S1 初步调查（Ⅰa + Ⅰb）
  ├─ 已查明根本原因 ──────────────────────→ S3 风险评估
  ├─ 信息不足（记录/图谱未提供）→ ⏸ awaiting_input
  │        （取数闸门：出 01b 请求单 → 挂起等回填 → 回判；见 §四之二）
  └─ 未查明 / 需重现证实
        │
        S2a 调查方案 →🔒方案审核 → 执行实验
              │
        S2b 调查报告（直接成文）→🔒报告审核 → S3
                                                  │
                            ┌─────────────────────┘
                            ▼
              S3 风险评估（两层）→ S4 CAPA → S5 自检+交付闸门 → S6 终审
```

**“已查明根本原因”路径不进 S2（也无调查报告）**；该路径下 S3/S4/S5 照常执行。
**报告已含风险/影响评估与 CAPA 时**，S3/S4 标注「见报告 §5 / §6」，不重做。

## 二、铁律（不可违背）

1. **人工闸门不可跳过。** 标 🔒 的节点必须停下来等人确认，不允许自动流转过去。
2. **每个节点产出必须落盘为独立文件。** 全链路只靠文件交接、不靠上下文；子代理看不到对话，但能读到 `02_investigation_plan_V1.0.md`。
3. **分支由数据决定，不是由默认路径决定。** 不做无谓的过度调查（见第六节跳过判据）。
4. **任一节点返回 `blocked`，整条链路挂起并报告原因**，不允许“跳过继续”。
5. **子技能不可用时挂起并提示缺失技能名**，不允许用自然语言“凑合”替代结构化分析。
6. **不越权**：不做放行决定、不代替质量负责人签字、不与药监直接沟通。
7. **节点入口自检（2026-09-27 补）**：进入任一节点前，先输出「节点入口检查」——① 上游产物是否已定稿（文件名 + 版本）② 该节点闸门是否已签（谁签 / 何时）③ 本节点输入清单。三项齐才动手。**不得以「内容已具备」「我自己审过了」口头过闸。**
8. **闸门签字人是人，不是 AI**：AI 只能产出「待签字的决策摘要 + 支撑证据索引」并留白签字栏；**审核意见必须落盘为独立文件才算完成**——只写在对话里的审核等于没审核（实跑已两次翻车）。
9. **结论变更必须传播（2026-09-27 补）**：任一节点的结论/出口发生变更时，必须列出**受影响的已产出下游产物**清单，逐条处置（回退重做 / 复核签认 / 降级并注明残留），处置记入 `_meta/revision_history.md`。不得只改当前文件、把下游留在旧口径上。

## 二之二、规则分档（2026-09-27 用户确认）

**规则只解决「可判定」的事；判断留给有证据的人。**

| 档 | 定义 | 判法 | 例子 |
|---|---|---|---|
| **硬闸门** | 有唯一答案、机器可判 | 脚本 / grep / 清单逐项打勾；不过即停 | 字段齐否、版本是否一致、留痕是否缺件、命名是否合规、时限是否登记、`_meta` 六件套是否齐 |
| **判断项** | 无唯一答案，靠专业判断 | **必答问题 + 需引用的证据 + 决断人**；**不得用硬规则套** | 根因是否成立、影响范围是否足够、信息需求是否充分、要不要上溯 L 层、定级 |

**三条纪律**：
1. 把判断项做成硬规则 = 替人做判断（越权）；把硬闸门交给「看着差不多」= 放行缺陷。
2. **新增任何条款时必须声明它属哪一档**（这是防“规则越加越多、反而没人真判”的关键）。
3. 硬闸门失败**不允许“口头通过”**；判断项**不允许“逐条打勾即通过”**——每条必须有引用的证据来源。

> **一页执行卡**：`references/gate_checklist.md`（逐节点：入口检查 / 产物 / 闸门 / 硬检查项 / 判断项必答问题 / 不过怎么办）。**执行时先读卡再动手。**
> **给人看的使用说明**（面向用户、非执行方）：随本 skill 一并交付的《质量事件主链_结构图与使用说明》——新人接手或用户问"这套怎么用"时先给这份。
> **闸门留痕（2026-09-27 定）**：每节点执行记录写 `<事件目录>/_meta/gate_log.yaml`（格式与三条硬闸门见卡 §四）；**判断项不得空答**（answer 或 evidence 为空 = 不过），不过的走「转提问 → 标 pending → 交决断人」。
> **独立抽检**：**S1 出口** 与 **S5 全绿** 处各派一次 gmp **轻量抽检**（模板 `qc-data-report-kanban-pipeline/templates/gmp_lightcheck_body.md`）——只核硬闸门项与 gate_log 完整性，不重做分析。
> **卡-skill 同步**：规则变更后跑 `scripts/gate_card_sync_check.py` 校验（卡里有、skill 里没有 = 漂移）。

> **gmp 离线时的降级代跑（2026-09-28 补）**：「挂起」是默认要求，但用户**显式要求走通全链**（如流程测试）且接受降级时，可允许 oos 代跑 ①（出 `03d_gmp_review.md`），**但必须双处留痕**：① `03d` 头部声明「gmp worker 离线，由 oos 代跑 C 式审核，非 gmp profile 独立执行，不替代人工终裁」；② `07_final_review.md` + `_meta/skill_invocations.yaml` 的 process_deviation_log 记降级。无用户明示则**只挂起，不代跑**（代跑 = 把 AI 终审换成同一 profile 自审，丧失组织隔离）。

> **双出口裁定点必须显式化（2026-09-27 补）**：S1 出口与 S2b 定稿**两个时点各停一次**，明确问「走标准出口（01+04+05）还是报告已含出口（03 含 §5/§6 即终局）」，把裁定结果（**裁定人 / 时间 / 结论 / 理由**）写入 `03c_skip_S3_S4.md` 或 `_meta/skill_invocations.yaml` 的 `process_deviation_log`（同一事件内二选一、全链统一）。**AI 不得自行切换，也不得在未被问过的情况下默认走其中一条**（2026-09-26 浊度检测仪一案：同一会话内两个方向各犯一次，均由用户口头纠正）。

**体系维度方向扫描（可选）**：`pharma-gmp-gap-scan` 挂点在 **S1 后 / S2b 前**；只给方向、**不得充当根因识别**；引用后须在报告中对 `state=suspect` 方向逐条交代（S5 检查）。

> **S1 的附加输入**：逐项排查需要证据粒度到「记录编号 / 页码 / 图谱编号」，S0 的六要素只携带记录本编号一项——S1 执行时**必须回到现场记录 / 表单 / 图谱**（不是缺陷，是本步的固有动作）。

> **「方案执行」可缺席（2026-09-25 实跑发现）**：当 S2a 的确认路径为**已有研究数据的整合与桥接论证**（不新设实验）时，节点表中「方案执行」这一行不存在。此时：① 跳过理由**必须写入报告**（见 §六 跳过判据）；② S2b 的证据来源为「**已有文件 + 桥接换算**」而非本次实验数据；③ 报告须明示桥接的**换算假设、口径、不可验证项、结论强度**——**桥接只提供"与…一致 / 支持"，不得写"证实 / 证明"**。

## 四、人工闸门 🔒（不可自动化）

| 闸门 | 谁签 | 签什么 |
|---|---|---|
| S1 后 | QA + 实验室主管 | 调查是否到位（**“是否成立”仅作参考**，事件已发起） |
| S2a 后 | 方案审核人 | 方案是否可执行（确认方法是否可证伪、分组是否防串扰） |
| S2b 后 | 报告审核人 | 根因依据链是否成立、影响评估与 CAPA 是否可接受 |
| S3 后 | 质量负责人 | 等级（Critical/Major/Minor）、波及范围、是否上报 |
| S4 后 | 质量负责人 / QA | CAPA 计划批准（含核查计划） |
| S6 后 | 质量负责人 / 审核人（gmp AI 终审之后的人工终裁） | D1 根因 L 层终点 + D2 定级 + D3 CAPA 批准 + D4 上报（gmp 已出红/黄项，人工对判断做最终取舍 + 签字） |

**技能只能在每个闸门处准备好“待签字的决策摘要 + 支撑证据索引”，不能代替签字。**

### 四之二、取数闸门（⏸ 非签字闸门；2026-09-25 补）

区别于 🔒 签字闸门：**取数闸门只取证据、不签字**，问的是“料到了没有”。

| 项 | 口径 |
|---|---|
| 何时触发 | 任一节点因**外部记录/图谱/参数未提供**而无法得出结论（典型：S1 回现场取证） |
| 状态 | `awaiting_input`（挂起待取数）—— **不是 blocked，也不是完成**；可挂任意时长、可跨会话 |
| 必产载体 | `0Xb_info_request.md` 请求单（需要什么／去哪查／用途／A必须或B可降级／答复形式／回填状态） |
| 如何问（CLI） | **请求单文件为主 + `clarify` 工具为辅**（一次 ≤5 问，只问 A 类关键项）—— 不用弹窗轮流问 N 项 |
| 恢复入口 | 用户说「**继续 <事件编号>**」／「**取数完成**」→ 只回判已回填项，未回填项留在清单 |
| 出口 | ① 补齐回判 → 原节点出口；② 用户选择带缺推进 → 缺项转 `pending_items` + 交付物声明 + **结论强度降级标注** |
| 禁止 | 挂起期间把节点标完成 / 把出口指向下游；缺项静默丢弃 |

> **带缺推进可贯穿全链至 S6（2026-09-28 标准筛 D26051 流程测试实测固化）**：用户明确「按流程测试走通」或选择带缺推进时，取数缺口（`awaiting_input` 未回填）**不阻塞** S2a→S2b→S3→S4→S5→S6，全链照常产出，但**每个受影响节点结论必须显式降级**：根因封顶「最可能原因（暂定）」、风险等级「Minor/暂定，A 类回填可上调」、历史数据「无法判定（时间窗+批次双缺口，连复验范围都圈不定）」、CAPA 责任人占位符照判 D4=1 不阻塞。降级≠省略：逐处标注 + `07`/`99` 带「带缺推进最终声明」（占位符清单 + 暂定结论清单 + A 类回填后重过 S5+S6 解除暂定）。**禁止**因带缺就跳过 S6 或把暂定写成定稿口吻。

> **与脱敏占位符的分工**：占位符（字段被脱敏）→ 判不阻塞（§九·五）；取证缺口（证据没拿到）→ 挂起待补。前者是数据形态，后者是证据缺失。

## 五、调用机制

**默认：同一上下文内串行调用**，不是派发 subagent。

| | 串行 in-context（默认） | Subagent 派发 |
|---|---|---|
| 上下文 | 累积，能看到全部中间产物 | 隔离，只返回摘要 |
| 中间细节 | 完整保留 | 丢失，靠文件交接 |
| 并行 | 不能 | 可以 |
| 适用 | 单条事件全流程 | 批量 / 长链 / 需组织隔离的调查 |

**子代理模式下的额外纪律**：
1. 派发时必须传入**前序节点产物文件的路径**，不能只说“去做 S4”。
2. 返回必须包含**结构化结论块（YAML）**，不能只回一段自然语言摘要。
3. 失败需返回 `blocked` + 原因，**不得自行降级输出“看起来像结论”的东西**。
4. `skill_invocations` 记录必须回传，并入 `_meta/skill_invocations.yaml`。

## 六、跳过判据与分支

| 节点/分支 | 条件 | 不满足时 |
|---|---|---|
| 历史数据可靠性（S3 第二层引用） | 根因涉及**方法/标准类（影响结果准确性）**、数据、仪器漂移、历史批次，或 gap-scan 的 D03 = suspect | 写“经评估无需历史数据可靠性评估，理由…”（**跳过的理由必须写进报告**） |

| 上报 + 独立调查组 | S3 判 Critical 或命中任一升级项 | 常规流程（见链外动作清单） |

> **「已查明路径」的两个合法出口（2026-09-26 实测补，防跳步/越步）**：S1 判「已查明根本原因」后，流程有两条合法终局形态，**取决于 S2b 报告是否已写出且内嵌 §5/§6**，切换由**用户裁定**：
> 1. **标准出口**：已查明路径本无 S2b → 交付物 = `01_initial_assessment.md` + `04_risk_assessment.yaml`（S3）+ `05_capa.yaml`（S4），S5 五道关对这组文件执行。
> 2. **报告已含出口（用户裁定优先）**：若调查链已写出 S2b 报告且**内嵌 §5 风险评估 + §6 CAPA**，用户可裁定**以该 S2b 报告为终局交付物**，S3/S4 **不单列节点、不另出 04/05 文件**，仅对该报告 §5/§6 做**复核签认**（查是否漏第二层 / CAPA 两分是否齐），然后直接进 S5。
> **关键纪律**：AI 不得在两条路之间擅自切换——既不得「S2b 已含 §5/§6 故跳 S3/S4」（越步进 S5），也不得「S1 已查明故 S2b 不该出」（越步删报告）。判据只有一条：**用户要哪条路**；选了「报告已含出口」须写进 `_meta/skill_invocations.yaml` process_deviation_log（本次实跑两方向都犯过，用户两次纠正后定案）。

> **方法/标准类根因的历史数据评估（2026-09-25 补）**：方法类问题的偏差作用于**一个时间区间内的全部批次**，不止单批——因此：① 时间窗起点 ＝ **该方法/标准生效的时点**（不是“上一次确认合格”），终点 ＝ 方法被纠正并确认；② 必须给出**偏倚方向**（偏高 → 假阳性；偏低/被低估 → **假阴性**，后者不得排除）；③ 本链只出【时间窗 + 批次范围 + 定性结论】，**批量回顾交** `qc-defect-analysis` 与 QMS 年度质量回顾；④ 若事件发生时体系**无“当场抓住”的手段**，则用该方法的历批数据**不能自证**，结论只能是“需复验 / 无法判定”，**不得写“历史数据可靠”**。

> **S1 的“需历史数据评估”标记是上游触发依据**：S1 在「检验方法」维度发现方法变更/方法偏倚时会打下该标记（见该 skill Ⅰb 节）；本行判据应优先认这个标记——**不能因为根因尚未定型就不启动评估**。

## 九·五、脱敏占位符处置口径（2026-09-25 用户裁决）

> **背景**：上传给大模型的数据**必须脱敏**，部分字段会**空着**，或写成 `xxx` / 随意填写 —— 本质是**占位符**，不是真实内容。**尺子不动，只是不阻塞。**

**三条原则**

1. **评分与判定照旧**：占位符**按“未提供”计**——该判缺项就判缺项、该判无效就判无效（例：S4 的 D4 因责任人为占位符而 <2 → 仍判“无效”）。**不得因为“知道这是脱敏”就给分或放行。**
2. **判定 ≠ 阻塞**：凡**因占位符**导致的“无效 / 不合格 / 缺项”，**不作为阻塞项**，流程继续往下推（S4 → S5 → S6）。写成 `xxx` 与写成错误内容是两回事：前者是**数据形态**，后者是**质量问题**。
3. **必须提醒补足**：识别到的每一个占位符**逐条登记**到 `_meta/pending_items.md`（字段 / 所在产物 / 期望内容 / 影响哪条判据），并在**交付物显著位置**声明数据形态：
   > 本次数据经脱敏，以下字段为占位符，须回填后方可正式使用：〔清单〕

**两类缺失必须分开（本口径的关键分界）**

| 类型 | 例子 | 处置 |
|---|---|---|
| **结构性缺失**（内容本身不存在） | 无根本原因陈述、无措施、无交付物、无核查计划 | **仍 `blocked`** —— 没有内容就没法往下推 |
| **字段级占位**（敏感字段脱敏） | 责任人／时限为 `xxx`／空／随意填写、人员姓名脱敏、批号部分掩码 | **判无效或缺项，但不阻塞**：登记待补 + 交付物声明 |

**纪律**：占位符不得被“合理化”成证据——责任人写 `xxx` 时不得据此判断“已有人负责”，报告中也不得出现“责任人为 xxx 已落实”这类叙述。审核人（S6/人）看到占位符必须能一眼分辨，**静默的空缺是最危险的形态**。
