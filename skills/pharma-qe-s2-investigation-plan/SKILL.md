# 质量事件流程 · S2a 调查方案（根本原因调查）

> **流程位置**：S2 前半。上游 = S1 的**初步调查结论**；下游 = 方案执行 → S2b 调查报告。
> **适用**：OOX / 偏差 / 无效测试。**缺陷不走本链**（缺陷走回复报告 8 段线，无方案环节）。
> **闸门**：方案**审核通过才能执行**。未通过 → 改方案重提。

## 一、本步做什么

把 S1 汇总出的「可疑点 / 需实验证实的原因」写成一份**可执行、可证伪**的调查方案。

**只写方案，不做实验、不出报告、不定根因。**

## 二、输入

- S1 的 `01_initial_assessment.md`（**结论段整段引用**，不重述）
- S0 的 `00_intake.md`（事件描述原句）
- 涉及的标准/规程编号与限度（质量标准、检验操作规程、仪器操作维护规程）

## 三、体裁：目的 / 范围 / 内容

### 1 目的（三段固定格式）

> 〔日期〕〔实验员/人员〕在〔地点/房间号〕进行〔样品/批次〕的〔检验项目〕检测，〔平行制备情况与结果〕〔超出《质量标准》接受标准 / 与典型图谱不一致 / 超出趋势，按事件类型选措辞〕，《〔质量标准/方法文件名称〕》（〔编号+版本〕）规定：〔限度，多药典并列写明；OOE 型写典型图谱与判定条款〕。经 Ⅰa、Ⅰb 阶段调查，初步怀疑可能原因为：〔怀疑原因 + 具体违背了哪条规程哪一款〕；为排查该原因，特制定本调查方案。

**写法要点**：
- 第 1 句 = 事件描述（谁、何时、何地、做了什么、结果如何、违背了什么规定）
- 结果措辞按事件类型选：**OOS 型**写「超出接受标准」；**OOE 型**写「与典型图谱/标准图谱不一致」或「方法外异常」；**OOT 型**写「超出历史趋势区间」
- 第 2 句 = **引用 S1 结论**：初疑原因必须**指到具体条款**（如《XX 操作规程》6.11.3.1），不写"操作不规范"这类无落点表述
- 第 3 句固定收尾："为排查该原因，特制定本调查方案。"
- 两个及以上初疑原因时，按"和 / 以及"并列列出

### 2 范围

一句话，限定到引发本事件的那一段：

> 本调查方案仅适用于引发〔事件编号〕的〔哪一环节〕原因调查。

### 3 内容

**3.1 原因识别**
- 3.1.1 **S1 排查结果概述**：列明 Ⅰb 已确认无异常的维度（人员操作、仪器、操作环节、方法、环境、取样、样品储存…），再落到**发现异常的细节**，把"异常细节 → 机理 → 结果偏高/偏低/异常"的因果链写透
- 3.1.2 **变量分解**：写出结果计算公式，逐个点名可能影响结果的变量（如含量公式中的 c 滴定液浓度、v 消耗体积、m 称样量），作为后续逐项调查的目录

**3.2–3.n 逐变量调查与排除**（每个变量一节）

每节结构固定：
1. 查看什么记录 / 做什么核对（注明记录编号与版本）
2. 数据表（原始数据 + 平均值 + RAD/RD 与接受标准，照实录）
3. 结论句："综上，**可排除**〔XX〕导致结果异常的可能"（不能排除的写明保留原因）

> 此层是方案的**骨架**：不做逐变量排除，直接给实验设计，审计会问"为什么只查这一个"。

**4 确认方法设计**

三列表，**每行一个候选原因**：

| 确认方法 | 可能结果 | 对应的原因 |
|---|---|---|
| 〔简述实验/分组设置〕 | 〔结果情形 A〕 | 〔对应哪个原因〕 |
| | 〔结果情形 B〕 | 〔对应哪个原因〕 |
| | 〔各组均不符合规定 / 均符合且无显著差异〕 | **需要进一步调查** |

设计纪律：
- **每个候选原因都要有"什么结果支持、什么结果否定"**——不可证伪的实验等于没设计
- 表内**必须保留"需要进一步调查"分支**：结果与预期全不一致时，方案要允许迭代，而不是硬套结论
- 结果判定要写**可量化的接受标准或差异判据**（超出接受标准 / 高于某组 / 无显著差异）

**4.1 操作方法**（分组执行细节）

每组一段，写清：分组目的 → 电极/仪器预处理（冲洗、活化时长）→ 空白与样品制备（平行份数、称样量、试剂体积）→ 每组之间如何衔接（上组结束后如何转换处理）→ 依据文件（操作规程编号与版本）→ 收尾（每份测定结束后如何处理）。

> 分组边界要防串扰：A→B→C 依次进行时，必须写明"组间如何清洗/活化"，否则结果无法归因。

## 四、产出与闸门

> **成文体裁**（本方案正文）：R0–R6、表格准入（数据留表 / 因果推理成句）、叙述先行、去内部编号——见 `pharma-report-narrative`（规则单一存放处）；成稿后同样过“脱表阅读关”。

- 产出：`02_investigation_plan_V1.0.md`（正文 + 编制/审核签署栏）
- 闸门：**方案审核通过 → 才能执行**；未通过按意见修订为 V2.0 再提
- 执行后的数据、图谱、记录编号交 S2b 调查报告使用

**方案审核意见必须留痕（2026-09-26 补）**：

方案审核不是只在对话里口头说一句"通过"——按编排器铁律"每个节点产出必须落盘"，**审核意见须写 `02b_plan_review.md` 独立文件**，含：
- 审核声明（AI 辅助判断、非代签；最终签字由方案审核人 🔒 确认）
- 红项（必判项，脱敏占位符按 §9.5 口径登记判不阻塞）
- 黄项（建议改进项）
- V1.0→V2.0 处置对照表（每条黄项怎么改的）
- 签字栏（角色/签名/日期/备注）

**为什么**：编排器铁律 2"产物落盘优先"——审计/S5/S6 时能回溯"方案审核谁做的、怎么判的、红黄项怎么处置的"。对话里的口头审核意见**不算留痕**，等于没审核。

**调查内容必须逐条回挂 S1 的结论与未排除项（2026-09-27 补）**：

方案 §3.3 的每一个实验 / 验证项（E1、E2…）都必须标注它对应 S1 的哪一条：

| 实验项 | 对应 S1 的（可疑点 / 未排除项 / 已查明结论） | 判定标准（什么结果说明什么） |
|---|---|---|
| E1 | | |

**规则**：① 不允许出现无法回挂 S1 的「凭空的实验」；② S1 判「已查明根因」时，实验项只能是**强化 / 可选核查**（不改变定性），**不得**写成「根因升级为唯一确定」这类暗示根因未定的措辞；③ **S1 出口在方案执行中途变更时，先按 S1 skill §八之三 做传播处置，再继续执行**。

> 实测（2026-09-26 浊度检测仪）：方案出了 E1–E5 复现设计，被用户质问「S1 结论是什么？E1–E5 与哪些因素对应？」——实验项与 S1 可疑点对不上，属典型缺陷。

**脱敏占位符在条款落点的处理（2026-09-26 补）**：

目的段初疑原因"必须指到具体条款"（铁律 3），但当用户按脱敏口径给的是占位符（规程编号=xx、条款原文=待回填）时：
- **不得替方案补造条款原文**（数据完整性铁律）
- **判不阻塞**：按编排器 §9.5 脱敏口径，占位符"按未提供计"但**不作为阻塞项**，流程继续推
- 方案 §6（待补清单）须**逐条登记**占位符字段 + 期望内容 + 影响哪条判据
- 02b 审核意见须**显式标注**"R 项=条款占位符，交审核人（🔒）判接受度"——接受则定稿，不接受则退 V3.0 补条款原文
- **不得静默放过**：条款占位符是红项（S2a 铁律"初疑原因不落条款审核必打回"），必须列红项让审核人决策，不能当黄项带过

## 四之一、机理层缺口检查（S2a 审核红项 · 2026-09-28 补）

**坐实一个结构层假设（如「多件同向超差」）不等于回答了根因。** S2a 方案在 S1 坐实结构证据（同周期/同批次/同方向）之后，必须补一层**根因机制假设 + 可证伪对照设计**，回答两个问题：

1. **物理/操作机理**（「什么作用使结果偏大/偏小/异常」）——如磨损累积速率、物料冲击变形、核查样失效；
2. **管理/机制层**（「现行周期/监控为何没先于验收暴露它」）——如校准周期内无中间预警点。

**红项判据（02b 必查）**：方案缺少机理假设或对照设计 → **打回**，不得以「S1 已坐实结构证据」为由放行。审核时逐条核对：每个坐实的结构假设是否有对应的机理子假设 + ≥1 个能把它与竞争假设分开的对照设计（周期趋势 / 备用件对照 / 预警点核查 / 工况匹配性）。
> 实测教训：某标准筛案 V2.0 把 01b 回填数值填入 V1.0 表格即判「H3 坐实」，漏了「孔径为何偏大 + 12 个月周期内为何无预警」——用户指出后补 §3.2.5 机理验证组（C1–C4）才过审。坐实「是什么」≠回答「为什么」。

## 四之二、确认方法与证据强度（2026-09-27 补）

每个待排除假设→**至少配一个能把它与竞争假设分开的对照设计**；对照设计可引用 `_knowledge/control-designs/`（阴性对照 / 同序列同批 / 留样重分取 / 两端夹逼 / 同期批对照）。

| 要求 | 内容 |
|---|---|
| 判定标准事先写死 | 每个实验/对照必须写“什么结果说明什么”——不得事后定调 |
| 对照可区分 | 对照必须能把两个竞争假设分开（否则实验无信息量） |
| 两个方向都有设计 | 既要有能**排除**的设计，也要有能**坐实**的设计 |

**证据强度规则（引用 `pharma-qe-s1-initial-triage/references/analysis-method.md` §⑤）**：排除 ≥1 条独立证据且指向该变量特有表现；坐实 ≥2 条且至少 1 条来自独立对照设计。

> 用过的对照设计在事件定稿后作为候选登 `_knowledge/候选队列.md`（两段式入库第一段），不得自行入库。

## 五、不做清单

不做 S1 的排查（引用）、不做实验、不出调查报告、不定根因、不定级、不写 CAPA。

## 六、已知陷阱

1. **跳过逐变量排除直接给实验**：方案的骨架就是"变量分解→逐项排除"，缺了这层只剩一个孤立的实验
2. **确认方法表没有"需要进一步调查"分支**：结果与预期不符时无法收场
3. **初疑原因不落到条款**：写"操作不规范"而不是《XX 规程》第 X 款，审核必打回
4. **分组不写组间清洗/活化**：A/B/C 结果无法归因，实验作废
5. **重述 S1 结论**：应整段引用 S1 的结论段，不重新叙述一遍排查过程
6. **把方案写成报告**：方案只写"打算怎么查、预期什么结果对应什么原因"，不写结论
7. **实验项不回挂 S1**：方案里出现与 S1 可疑点 / 未排除项对不上的实验（见 §四 回挂表）
8. **上游出口变更后方案不复核**：S1 出口中途变更，方案设计失去上游依据仍继续执行（应先做传播处置）
9. **坐实结构假设即收口，缺机理层**（2026-09-28 实测）：S1 回填坐实「多件同向超差」（结构证据）后，方案只填数值表就判 H3 坐实，未回答物理机理（磨损速率/物料冲击）与管理缺口（周期内无预警点），无对照设计 → 根因停在现象层，S2b 根因段无依据、S4 预防措施挂不住。修法见 §四之一：坐实结构证据后必须补机理子假设 + 可证伪对照（C1–C4 型），缺则 02b 打回。
10. **方案审核意见并入 03d/07 而不落独立 `02b_plan_review.md`**（2026-09-28 实测）：带缺推进或 gmp 离线代跑时，易把 S2a 审核直接写进 S6 的 `03d_gmp_review.md`——但方案审核（🔒 方案审核人）与 GMP AI 终审（S6）是**两道独立闸门**，合并后 S5 留痕齐备检查（`02b`/`03b`/`03d` 各须独立落盘）会判缺件。即便带缺推进/代跑，`02b_plan_review.md` 仍须独立成文件（内容可精简为"审核声明 + 红/黄项 + 签字栏"），不得并入下游文件。
