# 质量事件缺陷回复报告（C 式 8 维 + 5 级归因 + ALCOA+）

> 定位：**缺陷回复报告的撰写器。** 输入 = 检查人/用户的一段事件描述 + 调查事实；输出 = 缺陷回复**初稿**。
>
> **初稿定位（先读）**：初稿标准 = 结构完整 + 判断合理 + 允许留白，**不是"全面正确"**。
> - 结构完整：8 段齐全，每段有实质内容
> - 判断合理：不违反 L1 铁律，判断走了 L2 判据（judgment_trace 可查）
> - 允许留白：无法判断处标【待补充】，不硬编一个看起来对的答案
> - 覆盖范围、根因深度、风险落点的最终取舍在人工审核中综合决断——人的责任不交给 AI
>
> 审核层见 `oos-investigation-review`；数据分析层见 `qc-defect-analysis`；报告正文结构模板见 `fda-483-analysis/references/response-guidance.md`（按需加载）。

## 规则分层（L1 / L2 / L3，本文件组织方式）

| 层 | 位置 | 性质 | 违反后果 |
|---|---|---|---|
| L1 铁律 | 本文件「铁律」节 | 字面执行，不可违背，无场景例外 | 输出判无效 |
| L2 判据 | `references/criteria.md` | 分流条件，走完才得结论；层数封顶 2 层，例外标记化 | 须给出"为什么打破"的理由 |
| L3 案例 | `references/case_library/` | 判断校准锚点，按三标签检索 1–2 个 | 判断漂移时对照案例修正 |

分工：**铁律保底线，判据保分流，案例保校准。** 判据膨胀时（新增例外先问"加判据还是加标记"、同类偏差 ≥5 次触发修订评审）见 criteria.md 头部的反膨胀纪律。

## 何时使用

**使用**：**缺陷**（自检、QA 巡检、审计发现、检查人提出）要求走调查或写回复报告；或已起草的初稿需要 C 式结构升级。

> **本 skill 只服务缺陷回复线**（8 段结构 + R0–R6 语言规则 + J1–J4 判据 + 交付闸门）。**OOX（OOS/OOT/OOE）／偏差／无效测试由自己发起，走 S0–S6 质量事件主链**——终局报告是**三段式调查报告**（S2b `pharma-qe-s2-investigation-report`），**不经本 skill**。若请求是 OOX/偏差/无效的调查或报告 → 转主链（S0 登记 → S1 初步调查 → S2a 方案 → S2b 报告）。入口统一由 `pharma-qe-s0-event-intake` 按事件类型分流。

**入口路由**：
- 缺陷（自检 / QA 巡检 / 审计发现 / 检查提出），目标是**产出可送审的回复报告初稿** → 本 skill 直接走（默认路径）
- 涉及偏差且需要**组织隔离的调查**（数据完整性独立调查）→ 移交 `pharma-qe-orchestrator` 的质量事件主链（S0–S6）；**其终局报告由 S2b 出三段式调查报告，不回本 skill 出 8 段**
- **批量偏差台账体检（几百条 subagent 并行）不在本团队业务范围内** → 不默认移交质量事件主链（`pharma-qe-orchestrator`）；若确需批量分析，走 `qc-defect-analysis`（台账数据层 + 子集深度分析模式）

**不使用**：仅做数据分析（走 `qc-defect-analysis`）、仅审核已有报告（走 `oos-investigation-review` Mode A）、纯监管 483 回复（走 `fda-483-analysis` 主 SKILL）。

## L1 铁律（字面执行，不可违背）

1. **立论贴缺陷条款原文**：检查人提什么词，整份报告就围什么词立论（提"追溯性" → 追溯性/记录时点为纲；提"方式不统一" → 记录一致性为纲）。立论错了全篇跟着错。
2. **潜在风险 ≠ 既成事实**："未规定的潜在风险形态"（如未禁止提前填写日期）**只能写为潜在风险**，不得升级为既成事实或直接原因主因。既成事实与潜在风险在影响评估中**分两段陈述**（"实际发生情形核实" + "影响范围"）。
3. **概念性陷阱——上位要求不是下位逐文件复述对象**：数据完整性（同步/可追溯/如实）、GMP 通用要求等**上位体系性要求由 SMP/规程层统一承载一次即可**。下位 SOP 只补**本环节特有控制点**（如"机打标签日期须与实际取样时点一致"）。根因表述若写成"上位 SMP 被下位架空/下位承接上位缺口"即为概念错误，须清除。PA 措施里出现"逐环节核查下位承接情况"同理错——应为"评估模板补'可编辑记录日期时点一致性'项"。
4. **直接/根本原因必须拆开**：直接原因 = 该环节缺什么控制点；根因 = 为什么质量体系此前没拦住（机制层）。五级归因链（L0 现象 → L1 机理 → L2 直接原因 → L3 规定内容 → L4 规定来源 → L5 管理根因）作为分析工具完整走一遍；**终点在哪一层由 L2 判据 J1 决定，不由"必须到 L5"的机械规则决定，最终由审核人决断**（见 judgment_trace）。
5. **风险评估落点由 L2 判据 J2 决定**（替代旧版"落点固定=结果可靠性"）：落点主语 = 风险评估输出的风险点/缺陷质疑对象，不外推未质疑对象。"影响可忽略，风险较低"= 减责式表述，禁止。
6. **ALCOA+ 六属性逐项判**：可归属/可追溯/清晰/完整/可追溯扩展（含**及时性**）逐列判定。判定用 ✅/⚠️/❌ + 现状描述。"兜底满足"（如日期可经辅助记录印证）要写"⚠️ 兜底满足——依赖交叉印证，非受控设计"，不写"✅ 符合"。
7. **措施必须分短/中/长期 + 多层控制**：培训/SOP/工程/系统四层；短期 ≤1 周、中期 1–3 月、长期 >3 月。措施动词具体（修订/更换/增加/执行），禁止"梳理/了解/加强"模糊词。每条有责任人和交付物。
8. **有效性验证必须超越常规取样**：CAPA 有效性 = 观察期再发率 + 数据源明确。"完成 ≠ 有效"，关闭前必做核查计划（指标 + 基线 + 目标值 + 数据源 + 抓取时点 + 若无效处置）。
9. **文件操作规范**：所有修订在副本上进行（V1.0 → V2.0 → V3.0 …），源文件不动；修订历史保留近 3 个版本；末尾加「修订历史」段。
10. **叙述成文，不堆砌**：结构化分析（维度评分、根因链、ALCOA+ 表、CAPA）必须**改写成能读的叙述**再交付，禁止把带内部编号（F/V/CM/PA）的脚注铺满正文当成品。表格准入（数据留表 / 因果推理成句）、叙述先行结构、去编号规则**统一见独立 skill `pharma-report-narrative`**（2026-09-27 迁出，本线不再单列）。可追溯性靠报告末尾「事实与引用索引」承载（外置于 `_meta`）。
11. **终稿语言层**：R0–R6 与「脱表阅读关」见独立 skill `pharma-report-narrative`（泛化版，与质量事件线共用）；完整活规范（风险四拍模板、根因三层模板、证据分类法）仍在 `文档/质量事件/质量事件skill蒸馏原始文档/外部审计缺陷撰写规范.md`，写终稿前对照打磨。
12. **证据分类：再验证实验 ≠ 正常历史数据**：引用"未复现/未见类似"证据时，先分清是**为验证专门跑的主动实验**（证明性强）还是**常规检查自然产生的历史数据**（客观佐证，非证明）。定位"正常检查获得的数据"必须写成"查历史检测记录/图谱，未见类似"（佐证），不得夸大为"经再验证未复现"（那是主动证明）。异常值定性用"排除法 + 历史数据佐证 + 机理解释"三段合围，并说明该现象在方法固有局限内（如 CO₂ 干扰"检测中环境波动无法完全避免"），避免被读成操作失误。
13. **交付物与过程记录物理分层（L3 文件结构）**：报告交付目录三层分离——`01_narrative.md`（正文，唯一给人读的文件）/ `02_attachments/`（附件）/ `_meta/`（过程记录：skill_invocations、事实与引用索引、修订历史、待补充项、judgment_trace、问询日志）。**正文中禁止出现过程元数据**（grep 自检见 Phase 8）。
14. **判据调用留痕（judgment_trace）**：J1/J2/J3 每次判断输出附 judgment_trace（判据分支 + 参照案例 + 升级标记 + 待审核人决断项），写入 `_meta/judgment_trace.yaml`。这是"AI 判断非拍脑袋"的审计证据。
15. **人工决断声明**：根因深度终点、核实范围充分性、风险落点选择，技能只给判断 + 依据，**定夺权在审核人**。judgment_trace 中 `pending_reviewer_decision` 字段不可省略。

## L2 判据（判断走分流，细则见 references/criteria.md）

- **J1 根因深度 / 上溯必要性**（2026-09-27 定，取代旧「主判据=上位覆盖状态」）：
  ① **先判控制点归属层**（三问）——(a) 该控制点是「原则/流程/机制」类，还是「具体操作/单点」类？(b) 这类控制点在现行文件体系中传统落在哪一层（须举同类实例 ≥1 个）？(c) 换一台仪器 / 一个方法 / 一个物料，该要求是否仍成立？（成立→通用，可能属上位；不成立→本环节特有）。
  ② **再判该层缺口的性质**——**缺**（该管未管）／**断**（A 规定要评估、B 未承接）／**冲突**（两份文件对同一事要求不一致）。三者居其一才算缺口。
  ③ **定终点**：归属本环节（SOP/方法/记录）→ 缺口＝本环节未细化 → **终点 L3，补本环节控制点，不上溯、亦不需取证上位文件**；归属上位（SMP/管理规程）→ 上溯，须取上位文件编号 + 条款原文为证（取不到 → 不做单一层号断言，标 `pending_reviewer_decision`）。
  ④ **止损与升级**：归属上位但上位已覆盖 → 停 L3（本环节承接）；**同层同类**控制点在 ≥2 个独立文件/环节重复缺失 → `escalate_flag`（**跨层复制不算体系性**）；上溯一层必须产出**该层**措施，产不出 → 退回下层停（防过度归因）。
  ⑤ 举证责任：主张「归属本环节、不上溯」者须给三问答案 + 体系惯例依据；主张「上溯」者须给上位文件编号 + 条款原文。**终点由审核人决断**。铁律 3 是本判据的一般形式（上位要求由 SMP 层统一承载，下位 SOP 只补本环节特有控制点）。
- **J2 风险评估落点**：落点主语 = 风险点/缺陷质疑对象（追溯性→可追溯；数据可用性→可采信；不外推未质疑对象）。
- **J3 核实范围**：范围 = 缺陷质疑路径的边界，非批次全覆盖；路径外项一句话说明"不在本缺陷质疑路径上，故未排查"。用词纪律：禁止"默认合规/推定合格"（消极辩护），用"不在质疑路径上"（积极界定）。**范围充分性由审核人决断。**
- **J4 术语纪律**：缺陷条款（正式、有编号、逐条回应）≠ 检查人口头原话（非正式、必要时引用为辅助）。二者不可混用。

判据使用前：按三标签（缺陷类型 × 文件类型 × 质疑对象）检索 `references/case_library/` 最近似 1–2 个案例作为参照；判据模糊时以案例校准，不新造判据层级。

## 审核规则（GMP 审核意见必须过的一关）

**用户铁律**：GMP 审核后的意见，必须**先核对审核意见是否与相关内容的资料来源相符**，相符才可以按意见修订。审核意见引用的事实/数据/条款若与报告原文或既有核实事实不符 → 判为审核意见自身缺陷，不执行，并回写"不采纳理由"到审核意见文件。

典型不符场景：
- 审核意见要求"核实文件时序/引用关系"，但用户已核实"从一开始即如此" → 审核意见核实路径作废，按新事实改写
- 审核意见支持某根因表述，但该表述违反上位/下位概念分层 → 判为审核意见概念缺陷
- 审核意见要求措施分层错开时限，与用户已定的管理决策（同期限）冲突 → 降级为黄色项，注明"同期限为管理决策"

## 工作流

### Phase 0：缺陷定性（可选前置）

适用于**问题性质尚不明确**（不确定是否为 GMP 缺陷 / 属哪个主题域）；常规已定性事件跳过。**本步不产出等级**。

## 审核意见回写规则（按用户铁律）

收到 GMP 审核意见后，**先做资料来源相符性核对**，再决定按意见改还是驳回：

```
## 〇、资料来源相符性核对（新增节）
| 审核意见项 | 原意见内容 | 资料来源核对结果 | 结论 |
| R1 | … | 用户核实事实：… | R1 原核实项被推翻，按新事实改写 |
| R2 | … | 与用户管理决策冲突 | 降级为黄色项，注明"管理决策" |
| Y1 | … | 相符 | 并入正文 |
```

核对结果写入审核意见文件头部，被驳回的项在正文里标"不采纳理由"。

## Pitfalls

1. **根因机械挖到 L5**：J1 判 L3（上位已覆盖）时硬挖体系层 = 过度归因，审计员会问"凭什么说机制缺失？有证据吗？"。走判据，留 judgment_trace，终点交审核人决断。
2. **把潜在风险当既成事实**："未禁止提前填写日期"是潜在风险，写"未发生提前填写"（核实后）；不写"存在提前填写风险"（暗示已发生）。
3. **上位要求下位逐文件复述**：SMP 层"如实填写"不要求每份 SOP 复述，下位只补环节特有控制点。根因表述"上位被下位架空"是概念错误。
4. **落点写死"结果可靠性"**（旧病已修）：缺陷质疑追溯性 → 落点"可追溯"，不外推"结果可采信"。外推未质疑对象会引来"依据呢？"追问一片。走 J2。
5. **核实范围机械全覆盖**（旧病已修）：J3 路径边界 + 路径外一句话说明。用词禁"默认合规"（GMP 非默认合规逻辑，是风险导向的审查资源分配）。
6. **ALCOA+ 及时性被忽略**："记录是否于发生时记录"是 Timeliness，与记录方式不统一（Consistency）是两件事，分列。
7. **措施全压同一时限**：短/中/长期分层是 D6 评分锚点，全压 1 天 = 1 分。除非用户明确"同期限为管理决策"。
8. **"完成"≠"有效"**：措施完成不等于 CAPA 有效，关闭前必做有效性核查计划（再发率 + 数据源）。
9. **L4 事实未核实就定根因**：文件修订历史、风险评估记录、上位规程生效时序是 L4 事实，未核实前终点不得定稿。
10. **审核意见不与资料来源核对就执行**：审核意见引用的事实/数据/条款若与报告原文或既有核实事实不符，判为审核意见自身缺陷，不执行。
11. **SOP 修订时限忽略变更控制周期**：短期时限完成"修订 SOP"类措施若走变更控制，可能偏紧，需 GMP 审核人确认。报告中加提示。
12. **批量台账体检不在业务内**：几百条偏差台账 subagent 并行**非本团队业务**；批量分析走 `qc-defect-analysis`（数据层 + 子集模式）。事件调查（含组织隔离调查）走 `pharma-qe-orchestrator` 质量事件主链（S0–S6）——**不要再往已归档的旧编排 skill 里找路径**（其编排职责已全部并入编排器）。
13. **过程记录混入正文**（新坑，Phase 8 防）：skill_invocations / 事实索引 / 修订历史 / 待补齐项 / 问询记录 全部进 `_meta/`；正文出现即判不合格。
14. **判据嵌套膨胀**（新坑）：新增例外先问"加判据还是加标记"；判据 2 层封顶；同类偏差 ≥5 次触发修订评审。
