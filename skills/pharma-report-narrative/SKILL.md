# 报告成文体裁（R0–R6 泛化 · 表格准入 · 脱表阅读）

> **定位**：成文体裁的**单一存放处**。R0–R6 泛化自 `pharma-defect-response`（2026-09-27 迁出），由**缺陷回复线**与**质量事件线**（S2a 方案 / S2b 报告 / S3 / S4）共同引用，**各条线不再各留一套**。
> **何时用**：起草时按 R0–R6 写；每次成稿后过「脱表阅读关」（硬闸门）。
> **适用文档**：质量事件调查报告、缺陷回复报告、调查方案正文、风险评估与 CAPA 正文。

## 一、三条总则

1. **结构化分析必须改写成能读的叙述再交付**；可追溯性交给 `_meta`（事实与引用索引），不让脚注/内部编号淹没正文。
2. **数据可核、推理成句**。
3. **只动组织与语言层**，不动数据、编号、定级、措施要素、判据结论。

## 二、表格准入三规则（2026-09-27 定）

| 内容类型 | 处置 | 位置 |
|---|---|---|
| **数据类**（原始数据、对照结果、图谱/峰信息、统计量） | **留表** | **就地默认**：放在所服务的那一段/一节内，正文写「**见表 N**」；仅当数据成组、篇幅大、与正文论证弱相关时才移到报告末作附件（写「详见附件 N」） |
| **要素类**（措施表、效果验证表、签署栏、修订历史、检查项清单） | **留表** | 就地（跟所服务的段落同行） |
| 因果推理 / 排除逻辑 / 结论判断（回答「为什么」） | **必须成句**（证据→推断→结论） | 正文 |
| 判据 | **遮住表，正文能否读懂「为什么」**；读不懂 = 该段推理没写进叙述 | — |

**位置怎么选**（用户口径 2026-09-27）：就地与附后都可以，**默认就地**——数据放在所叙述的事情旁边，读者不必来回翻页。附后只用于成组、篇幅大、与正文论证弱相关的数据（大矩阵、逐批一览类）；其代价是会反复翻阅、影响整体阅读感，故不作默认。判据一句话：**读者读到这句判定时，需不需要这个数？** 需要 → 就地（数值入句 + 表紧随）；不需要 → 附件。

> 实测教训（2026-09-26 浊度检测仪 S5）：审核时把 §3.4“判定”从叙述句**改成了表格**——方向反了。

## 二之二、报告结构：方向内自洽 + 综述收口（2026-09-27 定 / 同日修正）

调查类正文（S2b 报告、缺陷线调查报告、S2a 方案正文）四段骸架：

| 段 | 内容 | 写法 |
|---|---|---|
| ① 场景还原（R0） | 该环节实际怎么运作 + 判定依据（不接受标准） | 运作方式、时间轴；不下判断 |
| ②③ 首次调查 / 进一步调查 | **每个因素/方向独立成段（或独立章节）**；段内三段式：**查了什么（事实）→ 分析（推理）→ 本方向结论（排除/坐实/不立项/未定/待补）** | 段落自洽：只读这一段，就能知道这个方向查出什么、因此判什么 |
| ④ 调查结论（综述） | 汇总各方向结论 + 方案预设情形对照 + **最终确定的初步原因/根本原因**（直接原因＋根本原因＋根因深度/落点） | 收口节：不重述各方向证据细节，只引结论 |

**为什么**：① 每个方向“查—析—断”齐备，审核可以一个方向一个方向地核对“证据→判断”是否成立（不必在两处对照）；② 方向独立成段，“哪个方向没查、哪个方向判不下去”一眼可见；③ 末尾综述收口，最终原因只有一个出处（不散在段中）。

**明确禁止的三种写法**（均为实测踩过的）：
- ✗ **把推理全抽出来集中放**（方向段只写事实，“已排除清单”另置一节）——读者要在两处之间来回对照，方向内不自洽；（2026-09-27 曾误释为用户意图，已作废）
- ✗ **整段混写不分方向**（所有方向挤成一段叙述）——查漏看不出、单方向无法核对；
- ✗ 方向段内只写“已排除”，**不写为什么排除**（结论无依据 = 审核必打回）。

**段内顺序**：事实句在前、分析句在后，用自然语言衔接即可，不必加“本方向结论：”小标签；但**段末必须有一句明确判定**（含判定词：排除 / 坐实 / 不立项 / 未定 / 待补做），供 ④ 综述引用与审核扫描。

**例外**：单方向事件（一眼可判的项，如计算错误、停电）可只写一段并直接进综述；须在文中注明理由。

## 二之三、报告模板（用户提供 · 2026-09-27 定）

**模板＝用户提供的真实报告全文**：`Quality_Events_Report/123456_某原料药含量异常调查报告_V2.0.md`。骨架：

```
# <检项/物料> 异常调查报告（<事件编号>）
报告编号 / 编制日期 / 调查周期
1 目的      （起止日期 + 人员 + 依据调查方案与阶段性报告编号 + 调查已结束 + 给出原因/最可能原因）
2 范围      （一句话：针对<事件编号>调查的总结、分析、评估与报告）
3 内容
  3.1 首次调查方案执行与结果
  3.2 进一步调查（按轮次 3.2.1 / 3.2.2 …）
  3.3 调查结论
  3.4 影响评估
  3.5 预防整改措施
附表 N     （数据类表格集中于此）
修订历史（版本表）
编制 / 审核 / 批准
```

**沿用的写法**：跨文件引用写「详见 <编号>-P01 调查报告」；数据表引用写「见表 N」（就地）或「详见附件 N」（另附）；措施表带「☒ 纠正 / ☐ 预防」勾选 + 负责部门 + 预计完成日期（可分短/中/长期）；效果验证给**量化**判定标准；修订历史放报告末。

**与本 skill 结构规则的对应**：模板原名与节号不变（3.1 首次调查方案执行与结果 / 3.2 进一步调查 / 3.3 调查结论 / 3.4 影响评估 / 3.5 预防整改措施）；其中 3.1 / 3.2 = **方向段（查—析—断同段）**，3.3 = **调查结论（综述收口）＋根本原因（含根因深度）**，3.4 = R4 风险四拍，3.5 = R5 措施＝根因镜像；数据表**默认就地（表 N）**，仅成组大表入附件。若将「场景还原与事件经过」单列为 3.1，则后续节号顺延一位（实测采用此式）。

## 二之四、文风：学范例的肌理（2026-09-27 定）

**范例锚**＝`references/exemplar_某原料药OOS报告全文_V2.0.md`（用户提供的真实报告全文）。写报告前先读它，而不是只读规则表——范例给的是句长/收口习惯/术语密度，规则表给不了。

| # | 规则 | 反例 → 正例 |
|---|---|---|
| 1 | **证据入句**：结论所依赖的那个数必须写进句子 | ✗「…无峰（详见附表 1）」→ ✓「空白与系统适用性溶液不含样品基质，在该位置均无峰；含样品的 STD 与样品均有峰」 |
| 2 | **删槽位标签**：不用「分析：」「本方向结论：」 | ✗「**本方向结论：候选 1 排除**」→ ✓「…故排除微限消毒剂残留引入，确认该峰由新厂家的某表面活性剂80 本征携带」 |
| 3 | **元话语出正文**：判据纪律/证据强度/脱敏口径不进叙事 | ✗「此处须写明一条判据纪律：…」→ ✓溶解进句子「STD 溶液因含样品基质，其出峰与样品出峰属同一变量，不能单独作为系统正常的证据」 |
| 4 | **以人/动作作主语** | ✗「该峰只在含样品的供试液中出现」→ ✓「为确认该峰是否来自样品，实验员将序列按是否含某表面活性剂80 分组核对」 |
| 5 | **段落节奏**：一段 150–350 字，段末一句概括收口；粗体只留给措施表与极少数关键判定 | 范例 §3.2.2.3 收口：「…这说明“忽高忽低”不是随机噪声，而是有结构的变异，来源是电极表面状态。」 |

**学肌理、不搬结构**：范例把数据表就地插在正文（可学），但把各类数据当分析轴（如「未活化组/活化组」）、无方向段与综述之分——结构仍按 §二之二 执行。

## 三、叙述先行结构（每节）

「做了什么 → 看到什么（数据表紧随） → 说明什么（一句『因此…』收口）」

节尾落点句即 R4 的落点句位置。**例**：本节先写“调阅 XX 记录、按 ZZ 方法复算” → 给数据表 → “因此可排除 XX”。

## 四、R0–R6（泛化版）

**R0 场景还原段（正文第一段固定模板）**：正文从“场景还原”起笔，不先下判断。100–200 字讲清该环节/记录/操作**实际怎么运作**（字段谁填、时间轴怎么走、操作顺序）；承接句“在该运作方式下……”；落点引出质疑/调查对象。
 · *质量事件线*：直接由 `01e_timeline.md`（时间线还原）改写。

**R1 叙事顺序**：一条时间轴（按时间排），禁止从“发现/检查”倒着讲。

**R2 因果分层主语切换**：直接原因主语 = **物质/现象**（回答“物理上怎么发生”，含机理 + 对比论证“为什么 A 发生而 B 未”）；根本原因主语 = **文件/机制/评估环节**（回答“管理上为何没拦住”）。**检验点**：两段圈出的主语必须是不同东西。

**R3 根因三层**：本点（这次为何发生）→ 横向（同类风险是否排查）→ 系统（前置机制为何失效 + 上位规程加条款）。层层变宽；**系统层的必要性由 J1 判定**——判 L3 时系统层一句话带过，不展开。**J1 的第一步是判控制点归属层**：擦拭/润洗/静置这类「该仪器该方法的特有操作」属本环节，终点取 L3，**不写成「上位未覆盖」、不硬扯体系性**；只有归属上位的缺口（原则/流程/机制类该管未管、规定之间有断点或冲突）才展开系统层。

**R4 风险段四拍**：后果推演（“可能导致…”假设性）→ 逐项排除（已处置/间隔短/使用前检查/机制判定）→ **落点句主语 = J2 判定的风险点/质疑对象**（不写“影响可忽略”=减责）→ 处置闭环 + 措施呼应。

**R5 措施 = 根因镜像**：每条措施回溯到一条根因/直接原因，动词具体到“加哪条文件哪款”；禁“加强培训/提高意识”无交付物措施。

**R6 正文去内部编号与元术语、保留 GMP 领域术语**：禁**本报告内部编号**（`F\d` / `V\d` / `CM` / `PA`）与**评估层元术语**（“维度”“锚点”“权重向量”“评分”）；段间用“综合以上/基于上述/因此”承接。**但 GMP 领域术语必须保留**：ALCOA+、可归属性/可追溯性/一致性/及时性、CQA、CPP、CSV、OOE/OOS/OOT、偏差、CAPA、变更控制、审计追踪等——白化反而丢精度。

## 五、脱表阅读关（硬闸门，2026-09-27 定）

成稿后**只读叙述、跳过所有表**，逐节验三项：

| # | 检查 |
|---|---|
| 1 | 结论能否**从叙述里**读出来（不是只在表里） |
| 2 | 依据是否在文中（记录/图谱/数据编号入句） |
| 3 | 是否存在“读不懂为什么”的段 |

**不过 → 回相应节点（S2b / 缺陷线 Phase）重写，不得交付。**
不适用 → 必须**写明理由**（如“本件无推理段”），**不得静默跳过**。
落点：质量事件线 = S5 交付闸门的**叙述关**；缺陷线 = Phase 8 自检同一动作。

## 六、转换边界与版本纪律

| | 内容 |
|---|---|
| **可改** | 组织与语言层（段落结构、句式、承接、去编号） |
| **不可改** | 数据、引用编号、定级、措施要素、判据结论 |
| **重写后** | 升版 + 修订历史注明“**仅语言层重写，结论未变**”（沿用 S5 版本重组口径） |

## 七、两条线适配差异

| 项 | 缺陷回复线（对外回复检查员） | 质量事件线（内部调查报告） |
|---|---|---|
| R0 场景还原 | 讲清该记录/环节的填写与流转方式 | 讲清该检验/操作的执行序列（源 `01e_timeline.md`） |
| R2/R3 分层与层级 | 直接原因 / 根本原因三层，层级用 J1 | 同 J1（归属层定终点：本环节 L3 / 上位层） |
| R4 风险段 | 落点句 = 缺陷质疑对象 | 落点句 = 质疑对象/风险点（§5 风险评估） |
| R5 措施 | 8 段回复报告的措施 | §6 CAPA（纠正/预防两分） |
| 参考范例 | 见 `pharma-defect-response` 参考范例节（某无机盐终稿、异常峰 V3.0 等） | **模板**＝`Quality_Events_Report/123456_某原料药含量异常调查报告_V2.0.md`（用户提供的真实报告全文；本 skill 另有副本 `references/exemplar_某原料药OOS报告全文_V2.0.md` 作文风锚）；**结构范例（2026-09-27 试写并经用户判定通过）**＝`references/examples/试写_浊度检测仪DEV123456_叙述体.md`、`references/examples/试写_某表面活性剂123456_叙述体.md` |

## 八、AI 易犯（实测）

1. **把叙述改成表格**（把“判定/因果”表化）——反向操作，最常见
2. **倒叙**（从“发现/检查”讲起）
3. **两段主语相同**（等于只有一个原因）
4. **风险落点句写成减责式**（“影响可忽略”）
5. **措施无交付物**（“加强培训”）
6. **白化 GMP 领域术语**
7. **语言层重写时顺手改了结论/定级**
