# 质量事件流程 · S0 事件登记与事件描述

> **流程位置**：质量事件单链的**第 1 步（S0）**。
> **本 skill 只做一件事**：把一起刚被发现/发起的质量事件，登记成**六要素齐全的事件描述**。
> **不做**：调查、根因、影响评估、定级、措施、报告成文、统计分析。这些分属 S1–S13，各有自己的 skill。
> 拆分理由：一个节点一条 skill，每步只读它需要的那一段，避免「一条 skill 什么都要管」。

## 何时使用

用户用自然语言发起一起质量事件，且尚未提供完整的事件描述。触发语句见下表。

**不使用**：已有完整事件描述而要写报告（→ 交编排器往下派）；只要统计/趋势（→ `qc-defect-analysis`）；只要审核已有报告（→ `oos-investigation-review`）。

## 触发语句（这条流程怎么开始）

| 触发语句（示例） | 事件类型 |
|---|---|
| 「我今天发起了一个 OOX」 | OOX（含 OOS / OOT / OOE） |
| 「（今天）发起了一个偏差」 | 偏差（含验证偏差） |
| 「发起了一个无效测试」 | 无效测试 |
| 「今天被提出了一条缺陷」 | 缺陷（自检 / QA 巡检 / 审计发现 / 检查提出） |
| 「（某项目）结果超标 / 结果不符合规定 / 结果异常」 | OOX（OOS 型）——**现象级描述** |
| 「仪器核查/校准/性能确认不通过，发起偏差」 | 偏差（**仪器不符合状态类**）——「不通过/不合格/异常」现象级表述也算命中 |

**现象级描述也是合法入口（2026-09-25 实测补）**：用户只说"结果超标"而不说"OOS"时，触发词表必须能命中。仅靠 OOX/OOS/偏差 这类**术语级**触发词会漏接——真实测试输入"包材水分结果超标"曾 0 命中。

**现象级描述须回问三件事**（不得自行归类）：① **OOS 还是 OOT**（超出标准 vs 超出趋势）；② **产品还是物料/包材**（决定是否触发供应商线）；③ 是**首次结果**还是**复测/多次结果**。

触发后**第一件事就是事件描述**；六要素齐了才交下游，缺要素先追问。

## 本步任务：六要素收集

事件描述不是「一句话说明发生了什么事」，而是**六个要素齐备**：

| # | 要素 | 要求 | 缺失策略 |
|---|---|---|---|
| 1 | **什么人** | 涉及谁：操作人 / 责任人 / 发现人（可多人） | 必填；确实未知 → 写「未知，待查」并入待核实清单 |
| 2 | **什么时间** | 事件发生时点；发现时点不同则并列 | ✅ 必填 → 追问 |
| 3 | **什么地点** | 车间 / 房间 / 仪器 / 系统 / 文件——定位到**可核查的最小单元** | ✅ 必填 → 追问 |
| 4 | **做了什么** | 实际动作序列（只写事实，不含推断） | ✅ 必填 → 追问 |
| 5 | **结果怎么样** | 客观结果：数据 / 记录 / 产品 / 批次受影响情况 | ✅ 必填 → 追问；潜在风险**另段陈述**，不得混入既成事实 |
| 6 | **违背了什么规定**（或与什么标准不符）／**被提出了什么问题** | 前者：条款编号 + 原文；后者：质疑问题原文 | ✅ 必填 → 追问；**区分条款原文 vs 口头原话** |

另需一并收集（下游要用）：

| 项 | 必填 | 缺失策略 |
|---|---|---|
| 涉事物料 / 批次 / 设备 / 文件 | ✅ | 追问（与要素 3/5 互为印证） |
| 既有事实清单（记录、SOP 编号、上位规程、检查人意见） | ✅ | 列清单追问 |
| 事件类型（OOX / 偏差 / 无效测试 / 缺陷） | ✅ | 无法判定则追问 |
| 责任人 + 完成时限 | 选填 | 留【待补充】，不硬造 |
| 事件编号 | 选填 | 留【待补充】 |

**仪器不符合状态类偏差的两项必收信息**（S1 影响回溯的方向判断依赖它们；缺了只能写「未提供，待查」，不得替用户推定）：

1. 核查期内该仪器**是否已用于实际检验**、涉及哪些批次——决定 S3 是否需要历史数据可靠性评估；
2. 本次核查**除异常项外的其他核查项**是否通过——判定仪器是「单指标异常」还是「全面失准」，影响根因方向与影响评估深度。

### 为什么六要素不是形式要求

- **要素 6 决定立论纲**：检查人提什么词，整份报告就围什么词立论（提「追溯性」→ 追溯性为纲）。缺 6 会导致**全篇立论错**。
- **要素 3/4 决定根因方向**：地点与动作序列缺失时，根因调查（S2）会跑偏到无关方向。
- **要素 1–5 决定事实边界**：边界不清则后面每一步都要返工。

## 产出

`00_intake.md`（模板：`references/intake-template.md`），含：六要素表 + 事件类型 + 涉事对象 + 既有事实清单 + 待核实清单 + 问询记录 + 缺口汇总。

落盘约定：事件目录（如 `deviation_DEV-xxx/`）下编号文件，交接靠文件不靠上下文。

## 完成判据（本步闸门）

- [ ] 六要素**逐项有值**（「未知，待查」也算有值，但必须登记进待核实清单）
- [ ] 事件类型已判定
- [ ] 涉事物料/批次/设备/文件已登记
- [ ] 既有事实清单已列，且区分「已核实」与「未核实」
- [ ] 每个追问都记入了问询记录

- [ ] 每条既有事实已标来源（本轮用户 / 原始记录 / 上轮产物）
- [ ] 事件号已追问并登记；目录名 = 事件号 + 主题（未提供时用占位符 + 登记）

**六要素不齐 = 本步未完成**，不得进入下游。

## 交接

| 方向 | 对象 | 交接物 |
|---|---|---|
| 上游 | 用户自然语言触发 | 触发语句本身 |
| 下游（**OOX / 偏差 / 无效测试**） | **S1 初步调查（Ⅰa+Ⅰb）**（`pharma-qe-s1-initial-triage`） | `00_intake.md` |
| 下游（**缺陷**） | **缺陷回复线**（`pharma-defect-response` 8 段回复报告）——缺陷不进调查主链，**无调查方案环节** | `00_intake.md` |

**按事件类型分流（2026-09-25 定）**：**缺陷**由外部提出（审计 / 自检 / 检查人），直接进缺陷回复线；**OOX／偏差／无效测试**由自己发起，进质量事件主链（S1 → S2a 方案 → S2b 报告 → 风险评估 → CAPA → 自检闸门 → 终审）。

移交时写明：事件类型、六要素缺口（若有）、待核实清单。**不替下游做判断**（不定级、不预判根因、不写措施）。

## 证据来源标注（2026-09-27 补，重跑 / 续办场景必做）

S0 的每一条「既有事实」必须带**来源标注**，三选一：

| 来源类型 | 写法 | 例 |
|---|---|---|
| 本轮用户提供 | 用户第 N 轮 / 日期 | 用户 2026-09-26 第 3 轮提供 |
| 本轮回填的原始记录 | 记录单 / 图谱 / 台账编号 | 记录单《TL2360》（E0001-R01-4.0-IP-11） |
| **上轮或历史会话产物** | **必须标「上轮产物，本轮未复核」** | 上轮 `quality_event_某某/01_...`（本轮未确认） |

**铁律**：上轮产物里的数据、候选根因、调查框架**不得直接当作本轮证据**——只能作**线索**并标来源，须由用户本轮确认/回填后才可引用。重跑时**先把旧目录移出工作路径**（改 `_archive/` 或改名），不要靠「我记得不用它」。

> 实测（2026-09-26 浊度检测仪一案）：产物里写了「本轮不复用历史取证事实」，仍在对话里把上轮结论当既成事实用了两轮（如「2026-06-09 复测合格」来自上轮产物），用户两次指出才发现。**隔离必须靠机制（路径隔离 + 来源标注），不靠承诺。**

## 事件号与目录命名（2026-09-27 用户定）

- 目录名 = `quality_event_<事件号>_<主题>`；**事件号优先取自 QMS 编号 / 偏差单号**，S0 必须追问并记录。
- **落盘根目录 = `<质量事件根目录>/`**（2026-09-27 用户裁决 · 方案 A）：事件目录**只建在该目录下**，不得建在其上层或其他位置。
- 事件号未提供 → 目录名写占位符 `待补事件号` 并登记 `pending_items`；**不得用主题或日期冒充事件号**。
- **同一事件只允许一个目录**：重入 / 重跑 / 补取证一律在原目录内更新（版本号或前缀区分），**禁止 `_rerun` / `_v2` 平行目录**。
- 目录名是重入检索的唯一身份锚（编排器「重入已有事件目录」条款依赖它）。

## 已知陷阱

1. **把推断写进「做了什么」**：要素 4 只写动作与事实，「他应该是忘了」属推断，进不了本步。
2. **潜在风险混入结果**：要素 5 只写客观结果；「可能影响后续批次」属潜在风险，另段陈述并标注。
3. **把口头质疑当条款**：要素 6 若只有口头原话（无条款编号），必须原样记录并标注「口头原话，待核条款」，不得自行拟一条规定。
4. **替用户补全**：缺什么问什么。「看起来合理的补齐」是数据完整性缺陷，不是效率。
5. **一步到底**：本 skill 收到「帮我写回复报告」时，先判断六要素是否齐：齐 → 交下游；不齐 → 只收集，不越步。
6. **重跑另建平行目录**（`..._rerun`）：同一事件出现两套产物目录，审计无法判定哪套有效。重跑在原目录内原地更新（版本/前缀区分）。
7. **事实不标来源**：把上轮产物的数据当本轮证据用（见「证据来源标注」节）。S0 所有既有事实逐条标来源，上轮产物只作线索。
